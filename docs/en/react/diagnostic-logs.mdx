# Diagnostic Logs

When a problem only reproduces on a device you cannot attach [DevTool](/guide/devtool/panels.mdx) to, ReactLynx can write a running account of what the framework is doing to the platform's native log. You turn it on at build time with an environment variable, then read it with the platform's own tooling — `adb logcat` on Android, the Xcode console on iOS.

Both switches below are off by default, and neither is meant to ship. The output is verbose enough to affect what you are measuring, so use these builds for diagnosis only.

## Framework diagnostics

`REACT_ALOG=true` makes ReactLynx report its own state transitions, on both the main thread and the background thread. Every line is prefixed with `[ReactLynxDebug]`:

```bash
REACT_ALOG=true rspeedy build
```

You get the `OnLifecycleEvent` payloads the main thread sends to the background thread, the snapshot instance trees on both threads before and after hydration, the events the background thread receives, list updates, and the patches applied back to the main thread.

Reach for this when the UI settles into a state you cannot account for — a component that never hydrates, an event that never arrives, a list that renders the wrong item. The trees printed before and after hydration usually show where the two threads' views of the tree diverge; see [Rendering Process and Lifecycle](./lifecycle.mdx) for what each stage is supposed to produce.

## Element API calls

`REACT_ALOG_ELEMENT_API=true` is one level lower. It logs every [Element PAPI](/api/engine/element-api.md) call the framework makes on the main thread — the create, append and update operations that build the element tree:

```bash
REACT_ALOG_ELEMENT_API=true rspeedy build
```

Each call is logged with its arguments, with elements rendered as `tag#uniqueId` so you can follow one element across calls:

```
[ReactLynxDebug] FiberElement API call #42: __AppendElement(view#3, text#7)
```

This is the last resort when the element tree does not match what your components describe. It is far noisier than `REACT_ALOG` — a single screen produces thousands of lines — so turn it on only once you know which interaction to look at.
