Today, we are happy to share that **Lynx 4.0 is now available**!

With this release, we are making it easier to build interfaces with AI, create dynamic elements in ReactLynx, and trace production errors and runtime UI nodes back to source code. Our AI tools help agents understand Lynx APIs and generate interfaces that Lynx can render.

For foldable devices, the host passes size changes to Lynx so pages can adapt to the window using familiar Flex layout and relative units. We are also expanding desktop CSS and Element capabilities, making `<webview>` and `<blur-view>` open source, and introducing global memory queries. Let's take a look at what you can build with Lynx 4.0.

## Adaptive Design

### Foldables

At its September event, Apple introduced its first foldable iPhone, [**iPhone Duo**](https://www.apple.com/newsroom/2026/09/apple-unveils-iphone-duo/), bringing new requirements for apps to adapt to dynamically changing screen configurations. Through our collaboration with TikTok, Lynx 4.0 now provides foundational support for foldable devices. When the window size changes, the host updates the [screen metrics](https://github.com/lynx-family/lynx/blob/4.0.3/platform/darwin/ios/lynx/public/LynxView.h#L244), [viewport](/api/lynx-native-api/lynx-view/update-viewport), and [GlobalProps](/api/lynx-api/lynx/lynx-global-props) for each [LynxView](/api/lynx-native-api/lynx-view) together. These updates trigger a new layout pass; in the default reactive mode, a GlobalProps update also triggers a ReactLynx [re-render](/api/rspeedy/react-rsbuild-plugin.pluginreactlynxoptions.globalpropsmode). Pages that already use [flexible layouts](/guide/ui/layout/flexible-box-layout) and [relative units](/api/css/data-type/length) can typically adapt to size changes caused by folding and unfolding without frontend code changes. See the [**Foldable Device Adaptation Guide**](/guide/inclusion/foldable-devices) for details.

### CSS Media Queries

To accommodate an increasingly diverse range of screen sizes and window configurations, Lynx 4.0 brings the core responsive-layout capabilities of [CSS Media Queries Level 4](https://www.w3.org/TR/mediaqueries-4/) to Lynx, including queries based on viewport width and height, aspect ratio, orientation, and pixel density; `min-`, `max-`, `and`, `or`, and `not`; comma-separated query lists; and modern range syntax such as `width >= 768px`. ## Native Backdrop Blur and Liquid Glass

Lynx renders directly to platform-native UI, so it can embrace native visual effects such as Liquid Glass from day one. After refining it for months in production apps, including TikTok, we are finally confident enough to ship it to the community.

Instead of providing separate primitives, we chose to encapsulate native backdrop blur on the Web, HarmonyOS, and iOS, Liquid Glass on iOS, and Lynx's Android blur implementation in an all-in-one `<blur-view>` element so that developers can use the same structure across platforms while progressively enhancing and gracefully degrading through platform-specific configurations.

Configure `<blur-view>` with [`blur-effect="glass"`](/api/elements/built-in/blur-view#blur-effect) to render Liquid Glass on iOS. Lynx exposes the key configuration of [`UIGlassEffect`](https://developer.apple.com/documentation/uikit/uiglasseffect) through [`glass-style`](/api/elements/built-in/blur-view#glass-style), [`glass-tint-color`](/api/elements/built-in/blur-view#glass-tint-color), and [`glass-interactive`](/api/elements/built-in/blur-view#glass-interactive). For grouped effects backed by [`UIGlassContainerEffect`](https://developer.apple.com/documentation/uikit/uiglasscontainereffect), use [`blur-effect="glass-container"`](/api/elements/built-in/blur-view#blur-effect) and control the distance at which glass elements begin to merge with [`spacing`](/api/elements/built-in/blur-view#spacing).

## Desktop Rendering

Lynx 4.0 expands the expressive power of CSS on desktop with custom text carets and multi-layer mask compositing in Clay on macOS and Windows.

### Custom Text Carets

Four new `-x-caret-*` properties let you style the caret in `<input>` and `<textarea>` with a custom [gradient](/api/css/properties/-x-caret-gradient), [width](/api/css/properties/-x-caret-width), [height](/api/css/properties/-x-caret-height), and [corner radius](/api/css/properties/-x-caret-radius):

```css
input {
  -x-caret-gradient: linear-gradient(to bottom, #00a6a6, #1479ff);
  -x-caret-width: 2px;
  -x-caret-height: 20px;
  -x-caret-radius: 1px;
}
```

### Multi-Layer Mask Compositing

With [`mask-composite`](/api/css/properties/mask-composite), you can combine multiple mask layers using `add`, `subtract`, `intersect`, and `exclude` to create cutouts and overlapping visual effects directly in CSS:

```css
.masked-view {
  mask-image: linear-gradient(#000, #000), linear-gradient(#000, transparent);
  mask-composite: exclude;
}
```

## ReactLynx

### `createElement` and `cloneElement`

ReactLynx now supports creating Lynx elements dynamically with [`createElement`](/api/react/Function.createElement) and [`cloneElement`](/api/react/Function.cloneElement). Use these familiar React APIs when an element's type is only known at runtime, or when you need to adjust the props of an existing element:

```tsx
import { cloneElement, createElement } from '@lynx-js/react';

export function StatusLabel({ selected }: { selected: boolean }) {
  const label = createElement('text', { className: 'label' }, 'Lynx 4.0');

  return selected
    ? cloneElement(label, { className: 'label label-selected' })
    : label;
}
```

This gives you more flexibility when building configuration-driven interfaces and reusable components. When the structure is already known at development time, we still recommend writing JSX directly so the compiler can analyze the static structure and optimize rendering. See [Compiler-Informed Rendering](/react/compiler-informed-rendering) for the trade-offs.

### Unified Debug Metadata

Production errors usually point to minified JavaScript, and errors on the Main Thread report bytecode locations that do not correspond to source lines and columns. To make them traceable, Rspeedy now collects JavaScript and CSS source maps, bytecode debug information, and UI source maps into a single `debug-metadata.json` for each build. You can use it to:

- **Map production errors to source**: restore the original file, line, and column from a bundled error stack, including errors thrown on the Main Thread.
- **Map UI nodes to source**: export the runtime UI tree from the client and find the JSX that created each node, helping you diagnose interface issues.

UI source maps are off by default. Enable them in `pluginReactLynx`:

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy';
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';

export default defineConfig({
  plugins: [
    pluginReactLynx({
      enableUiSourceMap: true,
    }),
  ],
});
```

Production builds remove `debug-metadata.json` from the output by default. To map production errors, keep and host the metadata for each build. To map UI nodes, the runtime also needs access to the matching `debugMetadataUrl`. See [Map Errors to Source](/rspeedy/map-errors-to-source) and [UI Source Map](/rspeedy/ui-source-map) for setup details.

## Generative UI

We have been actively exploring generative UI and previously released [support for A2UI](/blog/lynx-a2ui). Today, we are adding the `lynx-a2ui` Skill and support for the OpenUI format.

### A2UI

The [`lynx-a2ui`](/ai/skills/lynx-a2ui) Skill helps agents generate A2UI messages that use only the components, functions, and parameters declared in your application's catalog:

```bash
npx skills add lynx-community/skills -s lynx-a2ui
```

### OpenUI

[OpenUI](https://www.openui.com/docs/openui-lang) is a generative UI framework whose model-facing format, OpenUI Lang, is a compact, line-oriented language designed for streaming. Instead of generating executable code, the agent describes the interface with component expressions such as `Card(...)` and `Button(...)`, chosen from a library your application controls. [`<OpenUiRenderer>`](/react/genui/openui) from `@lynx-js/genui/openui` parses the output as it arrives and renders it as native UI with your registered ReactLynx components.

OpenUI programs can also hold reactive state and call tools. Use `$state` for state, `Query()` to read host data, and `Action()` to coordinate interactions. Queries and `Mutation()` writes only go through tools the host actually provides, and a `Mutation()` runs only when an explicit Action triggers it, such as a user clicking a submit button. This lets generated interfaces both display content and take part in your application's existing workflows.

## API Docs Skill

AI coding agents often carry Web conventions over to Lynx, producing properties or layouts that Lynx does not support. The [`lynx-api-docs`](/ai/skills/lynx-api-docs) Agent Skill gives agents a project-local reference for Lynx APIs, CSS, layout, and Elements, built from the public `@lynx-js/lynx-api-docs` package, so they can check what Lynx supports before writing code. For example, before building a scrolling list, an agent can look up the properties, events, and layout constraints of `<scroll-view>`.

Like the Generative UI Skills above, it is available from the community-maintained [Lynx Agent Skills](https://github.com/lynx-community/skills) repository:

```bash
npx skills add lynx-community/skills -s lynx-api-docs
```

For more ways to set up your project for AI agents, see [Lynx for AI](/ai/).

## Global Lynx Memory Queries

When your application hosts multiple Lynx pages, you may need to know which instances are still alive and where their memory is being used. With [global Lynx memory queries](/guide/performance/monitor-performance/global-memory-usage-query) on iOS and Android, you can asynchronously collect memory usage attributed to live Lynx instances in the current process. The results are grouped into categories such as Elements, UI/Views, Main Thread runtimes, and Background Thread runtimes.

Use this capability to request a snapshot when investigating memory pressure or other issues. To further trace references between JavaScript objects, use the query results to select an instance, then analyze its heap snapshot.
