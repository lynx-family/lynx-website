Desktop apps need access to the system and a fast way to iterate on UI. **[Lynxtron](/lynxtron/)** keeps the familiar Node.js host and uses Lynx to render the app’s interface, so the base runtime ships without a browser engine.

<span id="light-weight-and-fast" />

- **Download size.** The [Lynxtron 0.0.28 runtime ZIP](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) is **24 MB on macOS arm64** and **35 MB on Windows x64**. The [Electron 44.3.0 runtime ZIP](https://github.com/electron/electron/releases/tag/v44.3.0) is **130 MB** and **158 MB** on the same platforms.
- **Startup.** In a Windows production experiment, Lynxtron cut Douyin Desktop’s median time to first screen by **27%** versus the control group. Within the experiment group, P90 cold-start time to the first feed was **10.8 s** on the Lynxtron path versus **19.0 s** on the standard path (**43% lower**).

## Familiar Electron APIs for Developers and Coding Agents \{#multiplatform}

If you’ve built an Electron app, the startup flow will look familiar: wait for the app to be ready, create a window, and load the UI. Keep much of your Node.js host code and build the interface with Lynx. [See the migration guide.](/lynxtron/learn/Migrating-From-Electron)

```text
Electron    [Node.js main process] ↔ [Chromium renderer process]
Lynxtron    [One process: Node.js host ↔ Lynx UI]
```

```ts
import { app, LynxWindow } from '@lynx-js/lynxtron';

app.whenReady().then(() => {
  const win = new LynxWindow({ width: 800, height: 600 });
  win.show();
  win.loadFile('main.lynx.bundle');
});
```

You and your coding agent can [iterate on the UI in a browser](/lynxtron/learn/running-on-web), then verify desktop integrations in the app. In Cross-Platform Notes, one UI calls the same Notes API, backed by the file system on desktop and browser storage on the Web.

Bring an existing native renderer into a Lynx interface. In Native Texture Canvas, native code draws to an external texture while Lynx handles the controls and interaction. [See how Lynx native libraries work.](/lynxtron/Native-Libraries/Lynx-Native-Libraries)

For existing web pages, the optional [CEF WebView](/lynxtron/api/@lynx-js/cef-webview/index.mdx) provides a consistent Chromium engine. Its [0.0.28 download](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) is **126 MB on macOS arm64** and **161 MB on Windows x64**. [System WebView support](https://github.com/lynx-family/lynxtron/issues/395) is planned for apps that can use the platform’s own web engine.

Like Electron, Lynxtron supports [Node-API addons in the Node.js host](/lynxtron/Native-Libraries/NodeJS-Native-Modules). We’re also [bringing Node-API to more Lynx native platforms](https://github.com/lynx-family/lynx/discussions/845) so developers can reuse more of their native code.
