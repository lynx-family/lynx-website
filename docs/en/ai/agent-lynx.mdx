# agent-lynx

[agent-lynx](https://github.com/lynx-community/skills/tree/main/packages/agent-lynx) is a CLI that lets coding agents inspect and operate running Lynx applications. An agent can read the page structure, tap and fill elements, inspect logs, capture screenshots, and record performance traces, then use that feedback to verify its code changes.

Use agent-lynx for runtime debugging alongside [Agent Skills](https://github.com/lynx-community/skills) for Lynx development knowledge and [Lynx Docs MCP](lynx-docs-mcp.mdx) for documentation access.

## Get Started

### Install the CLI

agent-lynx requires Node.js 18.19 or later. Install the public npm package:

```bash
npm install -g agent-lynx
agent-lynx --help
```

You can also run it without a global installation:

```bash
npx --yes agent-lynx --help
```

The examples below use `agent-lynx`. Replace it with `npx --yes agent-lynx` if you use the one-shot command.

### Give Your Agent the Instructions

agent-lynx ships with skills that the agent can discover and read directly:

```bash
agent-lynx skills list
agent-lynx skills get lynx-devtool
```

`skills get` returns the instructions and lists the skill's reference and example files. It does not install a skill into your project. To make the DevTool skill available through your agent's automatic skill discovery, see [lynx-devtool](skills/lynx-devtool.mdx).

For example, ask your coding agent:

```text
Use agent-lynx to debug the currently open Lynx page. First read
`npx --yes agent-lynx skills get lynx-devtool`, then find the connected
client and session. Inspect the page and console, reproduce the issue,
fix the source code, and verify the result with a fresh screenshot.
```

You can also add the instruction to read `lynx-devtool` before runtime debugging to your project's [AGENTS.md](agentsmd.mdx).

### Connect a Lynx App

1. Run [Lynx Explorer](/guide/start/quick-start) or your own app with [DevTool integrated](/guide/start/integrate-lynx-devtool).
2. Enable **Lynx Debug** and **Lynx DevTool** in the app. For a physical device, connect it to the computer running agent-lynx and complete the platform's debugging setup. See [device connection setup](/guide/devtool).
3. Open a Lynx page in the app, then discover its client and session:

```bash
agent-lynx list-clients
agent-lynx list-sessions --client <clientId>
```

A **client** is a running app; a **session** is a Lynx view or debugging context within that app. Use the IDs returned by these commands. When several targets are connected, pass `--client <clientId>` and `--session <sessionId>` to subsequent page commands so they operate on the intended page.

Device commands automatically start a shared local connector daemon. Keep the default daemon connection for snapshot refs, interactions, and ReactLynx inspection so separate CLI calls share the same connection and cached refs.

## Inspect and Interact with a Page

### Read the Page and Act on Elements

Capture a compact element tree:

```bash
agent-lynx snapshot
```

The output assigns refs such as `@e1` to elements. Use refs from your own output in the commands below; the sample refs are placeholders for the corresponding text, input, button, or scroll container:

```bash
agent-lynx get text @e1
agent-lynx get style @e1 --property color,width
agent-lynx fill @e2 "Alice"
agent-lynx snapshot
agent-lynx tap @e3 --snapshot
```

After an interaction, read the refreshed snapshot before choosing the next target. For a scroll container in that snapshot:

```bash
agent-lynx scroll @e4 --direction down
agent-lynx snapshot
```

Refs belong to the selected page's cached snapshot. Capture a new snapshot after navigation, reloads, or UI changes, and use the latest refs.

### Capture a Screenshot

```bash
agent-lynx screenshot --annotate -o ./page.jpeg
```

This captures the page and refreshes the snapshot. Image labels such as `[3]` correspond to refs such as `@e3`, so an agent can identify a visible target and interact with it. Add `--json` to receive the screenshot path, dimensions, and the same fresh snapshot as structured output.

To capture the full screen, use `agent-lynx screenshot --fullscreen -o ./screen.jpeg`. Use `--annotate` and `--fullscreen` separately.

### Inspect Logs and Find Source Code

```bash
agent-lynx get-console --limit 50
agent-lynx get-sources
agent-lynx get-source-info @e1
```

`get-console` includes the VM thread and available stack traces. Use `--watch` to stream new logs while reproducing an issue. `get-source-info` maps an element to source when the page provides [UI source-map metadata](/guide/devtool/ui-source-map).

For a graphical inspector connected to the same session, run `agent-lynx inspect` and open the printed URL. For lower-level debugging, consult `agent-lynx evaluate --help` and `agent-lynx cdp --help`. Lynx supports a subset of CDP; check the [Lynx CDP reference](/api/cdp/api-ref) before sending a method.

### Inspect ReactLynx Components

For a development build with [ReactLynx DevTools enabled](/guide/devtool/panels/preact-devtools-panel):

```bash
agent-lynx reactlynx tree
agent-lynx reactlynx component @c1
```

Component refs (`@c1`) differ from element refs (`@e1`). Use `agent-lynx reactlynx link @e1` to find an element's associated component, or `agent-lynx reactlynx link @c1` to find a component's host element. Capture a snapshot and component tree first, and use the refs they return.

## Record and Analyze a Performance Trace

Start tracing **before opening or reloading the target page** to include its first frame. Use the same client throughout the recording:

```bash
agent-lynx trace start --client <clientId>
agent-lynx open '<bundle-url>' --client <clientId>
# Reproduce the interactions you want to measure, then stop recording.
agent-lynx trace end --client <clientId>
```

Replace `<bundle-url>` with a bundle URL reachable by the app, such as the URL printed by your project's development server. agent-lynx opens the URL; run the project's build or development server separately.

`trace end` returns a stream handle. Substitute that value for `<stream>` to download the trace:

```bash
agent-lynx trace read-data --client <clientId> --stream <stream> -o ./page.pftrace
agent-lynx trace event-summary ./page.pftrace --json
agent-lynx trace query ./page.pftrace --sql "SELECT name, COUNT(*) AS count FROM slice GROUP BY name"
```

`trace event-summary` and `trace query` analyze local files without a connected device. For guided performance diagnosis, load the analysis skill with `agent-lynx skills get lynx-trace-analysis`; see [lynx-trace-analysis](skills/trace-analysis.mdx).

If tracing asks you to enable debugging and restart the app, restart it and run `trace start` again before opening the page. Trace support depends on the app's build; see [trace recording requirements](/guide/devtool/trace/record-trace).

## Use the Connector API

For JavaScript or TypeScript automation, install agent-lynx in the project so imports can resolve:

```bash
npm install agent-lynx
```

```js
import { createDefaultConnector } from 'agent-lynx/connector';

const connector = createDefaultConnector();
const clients = await connector.listClients();
console.log(clients);
```

The default connector shares the daemon connection with the CLI. See the [Connector API examples](https://github.com/lynx-community/skills/blob/main/packages/skills/lynx-devtool/references/library-usage.md) for session discovery and CDP workflows.

## Troubleshooting

| Symptom                                      | What to check                                                                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No clients are listed                        | Keep the app running in the foreground, enable Lynx Debug and Lynx DevTool, and check the device connection. On Android, confirm USB debugging is authorized. |
| The wrong page is selected                   | Run `list-clients` and `list-sessions` again, then pass both target IDs explicitly.                                                                           |
| An element ref is missing or stale           | Run `snapshot` again and use refs from its latest output for the same client and session.                                                                     |
| The ReactLynx tree is empty                  | Check the selected session and use a development build with compatible ReactLynx DevTools.                                                                    |
| Source information is unavailable            | Enable UI source-map generation and make the matching debug metadata reachable by the tooling.                                                                |
| The agent reports a network-permission error | Allow the agent to reach the local daemon and device services. See [Codex network configuration](skills/lynx-devtool.mdx#codex) if applicable.                |

Use `agent-lynx daemon status` to inspect the local daemon and `<command> --help` for current options. `--no-daemon` is for explicit direct-transport workflows; snapshot refs, ref actions, `screenshot`, and ReactLynx commands require the daemon.

## Existing Skill and MCP Workflows

If you previously used `lynx-devtool` or skill-local trace scripts, use `agent-lynx` as the CLI entry point and load the current DevTool instructions with `agent-lynx skills get lynx-devtool`. The [trace workflow above](#record-and-analyze-a-performance-trace) replaces the separate recorder-script entry point.

For clients that require MCP tools, the [Lynx DevTool MCP setup](lynx-devtool-mcp.mdx) remains available. agent-lynx can be used directly by coding agents that can run shell commands. [Lynx Docs MCP](lynx-docs-mcp.mdx) continues to provide documentation access.
