# Upgrade from Rspeedy

Rspeedy ([`@lynx-js/rspeedy`](/api/packages/rspeedy)) is Lynx's previous build tool. Built on Rsbuild, it provides the `rspeedy` CLI and uses `lynx.config.ts` for configuration. We now recommend **Rsbuild with `pluginLynx`**, using Rsbuild's configuration and plugin ecosystem directly.

Rspeedy is still maintained, and existing projects can continue to use it. The following steps migrate a project to Rsbuild.

## Migrating an Rspeedy project

Rspeedy and `pluginLynx` share the same build engine. Migration mainly involves dependencies, CLI commands and configuration; application code does not need to be rewritten.

1. Replace the dependency: drop `@lynx-js/rspeedy`, add [`@rsbuild/core`](https://www.npmjs.com/package/@rsbuild/core).
2. Point the scripts at the other CLI — `rspeedy dev`, `rspeedy build` and `rspeedy preview` become `rsbuild dev`, `rsbuild build` and `rsbuild preview`.
3. Rename `lynx.config.ts` to `rsbuild.config.ts` and take `defineConfig` from `@rsbuild/core` instead of `@lynx-js/rspeedy`.
4. Switch `types` in `tsconfig.json` from `@lynx-js/rspeedy/client` to `@rsbuild/core/types`.

Then adjust the config itself:

- **[`source.entry`](https://rsbuild.rs/config/source/entry) and [`output.filename`](https://rsbuild.rs/config/output/filename) take the object form.** Rspeedy also accepts a plain string; Rsbuild does not.
- **Lynx's own options move into `pluginLynx`.** [`output.filename.bundle`](/api/build/output/filename/bundle) and [`performance.profile`](/api/build/performance/profile) are Rspeedy config keys, not Rsbuild ones, so they belong in `pluginLynx({ ... })` — which also means applying that plugin explicitly, since the automatic application uses default options.

## Differences between Rspeedy and Rsbuild

Both approaches use `pluginLynx` to build Lynx bundles. The main differences are their CLI and configuration interfaces:

|                         | Rspeedy                                                                            | Rsbuild with `pluginLynx`                                     |
| ----------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| CLI                     | `rspeedy dev / build / preview / inspect`                                          | `rsbuild dev / build / preview / inspect`                     |
| Configuration file      | `lynx.config.ts`, with `defineConfig` from `@lynx-js/rspeedy`                      | `rsbuild.config.ts`, with `defineConfig` from `@rsbuild/core` |
| Configuration scope     | A strictly validated subset of Rsbuild configuration, with some options restricted | The full Rsbuild configuration and plugin ecosystem           |
| Lynx-specific options   | Set directly in the configuration file, such as `output.filename.bundle`           | Pass to `pluginLynx({ ... })`                                 |
| Shorthand configuration | `source.entry` and `output.filename` accept strings                                | Use object form                                               |
| Build-time types        | `@lynx-js/rspeedy/client`                                                          | `@rsbuild/core/types`                                         |

For example, Rspeedy does not pass through options such as `tools.postcss`, and fixes values such as `output.charset` and `output.polyfill`. With Rsbuild, follow the [Rsbuild configuration reference](https://rsbuild.rs/config/) directly. See the [Lynx build configuration reference](/api/build) for Lynx-specific options and changed defaults.
