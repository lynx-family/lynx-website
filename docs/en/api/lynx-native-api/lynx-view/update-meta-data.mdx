# updateMetaData

<APISummary />

Using [LynxUpdateMeta](/api/lynx-native-api/lynx-update-meta) to update `LynxView`, it is the main entrance for the client to update template data.

This page is the reference for the complete update-method signatures, parameters, types, and version notes on every platform.

## Platform Mapping

Native platforms pass a [LynxUpdateMeta](/api/lynx-native-api/lynx-update-meta) object that carries the template data and global props. On the Web, [`<lynx-view>`](/api/lynx-native-api/lynx-view/lynx-view) has no metadata structure: its methods accept the data directly.

| Platform      | Update method                       | Input                                                  |
| :------------ | :---------------------------------- | :----------------------------------------------------- |
| Android       | `updateMetaData`                    | `LynxUpdateMeta`                                       |
| iOS           | `updateMetaData:`                   | `LynxUpdateMeta`                                       |
| Desktop (C++) | `UpdateData`                        | `std::shared_ptr<lynx::pub::LynxUpdateMeta>`           |
| Web           | `updateData` and `updateGlobalProps` | Template data or global props as a [`Cloneable`](#cloneable) value |

## Syntax

### Android

```java
public void updateMetaData(LynxUpdateMeta meta);
```

#### Parameters

- `meta`: Lynx template update metadata, developers use this data structure to specify the optional data content of the update template.

### iOS

```objc
- (void)updateMetaData:(nonnull LynxUpdateMeta *)meta;
```
#### Parameters

- `meta`: Lynx template update metadata, developers use this data structure to specify the optional data content of the update template.

### Web

:::info

The signature below applies to `@lynx-js/web-core` 0.18.0 and later. In earlier versions, the second parameter of `updateData` is required and declared as `updateDataType: UpdateDataType`; since 0.18.0, it is the optional `processorName?: string`. See the [0.18.0 changelog](https://github.com/lynx-family/lynx-stack/blob/main/packages/web-platform/web-core/CHANGELOG.md#0180).

:::

```ts
updateData(
  data: Cloneable,
  processorName?: string,
  callback?: () => void,
): void;
updateGlobalProps(data: Cloneable): void;
```

#### Parameters

- `data`: Data to be updated, should be `structuredClone` compatible. For `updateData`, it is the template data; for `updateGlobalProps`, it is the global props.
- `processorName`: Optional. The name of the `dataProcessor` that processes `data` before the update. If it is omitted, the default `dataProcessor` is used. See [Using Data from Host Platform](/guide/use-data-from-host-platform).
- `callback`: Optional. Called after the update is applied.

#### Cloneable

The data accepted by the `<lynx-view>` methods, including [`sendGlobalEvent`](/api/lynx-native-api/lynx-view/send-global-event), is declared with the `Cloneable` type:

```ts
export type Cloneable<T = string | number | null | boolean | undefined> =
  | T
  | Record<string, T>
  | T[]
  | Array<Record<string, Cloneable>>;
```

### Desktop (C++)

```cpp
void UpdateData(std::shared_ptr<lynx::pub::LynxUpdateMeta> update_meta);
```

#### Parameters

- `update_meta`: The update metadata used to provide template data and global props.
