# `<scroll-view>`

<APISummary />

Basic scrolling component supporting both horizontal and vertical scrolling. When its content area is larger than its visible area, it allows users to scroll to reveal more content.

## Usage

### Horizontal and Vertical Scrolling

`<scroll-view>` supports one scrolling axis at a time, configured by `scroll-orientation` (`vertical` by default). Give the view a bounded size along that axis so its content can exceed the visible area.

`<scroll-view>` uses [linear](/guide/ui/layout/linear-layout.mdx) layout for its direct children, with the direction determined by `scroll-orientation`. To use Flexbox or another layout inside the scrolling content, place the content in a child `<view>`.

### Sticky Capability

Set the `sticky` attribute on a direct child of `<scroll-view>` to keep it at the configured edge offset as the content scrolls past it. For vertical scrolling, for example, use `sticky` with `top: 0`.

:::tip
`sticky` can only be set for direct child nodes of `<scroll-view>`. On <AndroidOnly />, you need to add the `flatten={false}` attribute to `sticky` nodes.

The scroll container lays out its direct children linearly; this does not restrict the layout inside each child. A wrapper for more complex content can look like this:

```tsx
<scroll-view scroll-orientation="vertical" style={{ height: '300px' }}>
  <view style={{ display: 'flex', flexDirection: 'row' }}>
    <text>First item</text>
    <text>Second item</text>
  </view>
</scroll-view>
```

:::

## Performance Optimization Suggestions

`<scroll-view>` creates all supplied child nodes and does not virtualize or recycle them. Large amounts of content can increase initial rendering time and memory usage.

For long or growing collections, prefer [`<list>`](./list.mdx). Exposure events can help defer expensive work, but do not turn `<scroll-view>` into a virtualized list or automatically remove off-screen nodes.
