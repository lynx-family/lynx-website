# 构建 Lynx 应用

构建把应用的代码、样式和资源转换为宿主可以加载的 [_Lynx Bundle_][Lynx Bundle]。开发时，构建工具通过开发服务器和热更新把修改同步到设备；发布时，它生成生产产物，并提供调试信息，帮助你分析性能和定位线上问题。

Lynx 使用 [Rsbuild](https://rsbuild.rs/zh/) 和 [`pluginLynx`] 完成这一过程。TypeScript、CSS、静态资源和插件接入沿用 Rsbuild 的能力；`pluginLynx` 负责 Lynx 特有的部分，包括双线程代码的构建、Bundle 编码，以及适配目标 [_Lynx Engine_][Lynx Engine] 的输出。本章介绍这些环节如何配合，各专题进一步说明具体用法。

## 构建工具与开发流程 {#getting-started}

新项目推荐使用 Rsbuild + `pluginLynx`。[快速开始](/guide/start/quick-start.mdx)介绍如何创建项目、启动开发服务器并在设备上运行应用。ReactLynx 项目通过 [`pluginReactLynx`](/api/packages/react-rsbuild-plugin/functions/pluginReactLynx) 接入构建，它会自动应用 `pluginLynx`；[`pluginQRCode`](/api/packages/qrcode-rsbuild-plugin) 提供扫码打开应用的入口。

项目在 `rsbuild.config.ts` 中配置，用 `rsbuild dev` 开发、`rsbuild build` 构建生产产物，`rsbuild preview` 预览产物。配置可以使用 Rsbuild 的完整能力；[`rsbuild.config.ts` 参考](/api/build)说明了 Lynx 新增的选项和调整过的默认值。需要设置 Lynx 专属选项时，在 `plugins` 中显式配置 `pluginLynx`。

现有的 Rspeedy 项目使用同一套构建引擎。两者的配置差异、维护方式和迁移步骤见 [Rspeedy](./rspeedy.mdx)。

## 代码、样式与资源

应用的日常编写方式与 Rsbuild 项目相通，但运行环境是 Lynx。构建工具负责处理源码和资源；具体可以使用哪些元件、CSS 属性和运行时 API，由 Lynx 决定。

### 样式 {#styling}

构建支持 CSS Modules、全局 CSS、Sass、Less 和 PostCSS。CSS 会被解析并编码进 Bundle；组件作用域、样式继承等行为则由 Lynx 的配置控制。[样式](./styling.mdx)介绍这些方式如何配合。使用 [Tailwind CSS](./tailwind.mdx) 时，还需要 `@lynx-js/tailwind-preset` 来适配 Lynx 支持的样式能力。

### TypeScript {#typescript}

Rsbuild 处理 `.ts`、`.tsx` 和路径别名等通用构建需求。Lynx 还提供全局对象、元件和原生模块的类型；你可以扩展这些类型来描述应用自己的数据与宿主能力。具体见 [TypeScript](./typescript.md)。

### 静态资源 {#static-assets}

图片、字体等资源可以在代码或 CSS 中引用。构建会把它们作为单独文件输出，或将小文件内联为 data URI；`public/` 中的文件则直接复制到输出目录。资源路径、URL 前缀和内联方式见 [Rsbuild 静态资源指南](https://rsbuild.rs/zh/guide/basic/static-assets)，Lynx 的默认内联阈值见 [`output.dataUriLimit`](/api/build/output/data-uri-limit)。

### 模块解析 {#module-resolution}

同一个依赖包可能同时提供 Web 和 Lynx 版本。`pluginLynx` 优先选择包的 `lynx` 导出条件，让应用使用适合 Lynx 的实现。路径别名仍通过 `tsconfig.json` 或 Rsbuild 的 [`resolve.alias`](https://rsbuild.rs/zh/config/resolve/alias) 配置，文件扩展名的解析规则见 [`resolve.extensions`](/api/build/resolve/extensions)。

## Bundle 与运行环境 {#bundles}

每个应用入口生成一个 `.lynx.bundle`，其中包含主线程代码、后台线程代码、样式和页面配置。宿主把它交给 Lynx Engine 加载，因此构建时也需要考虑宿主使用的引擎版本。Bundle 的 [`engineVersion`] 决定它所需的最低引擎版本；[Lynx Bundle 与兼容性](./lynx-bundle.mdx)介绍 Bundle 的内容、双线程构建和版本兼容策略。

### 构建输出文件 {#output-files}

生产产物默认写入 `dist/`。除应用 Bundle 外，还可能有懒加载 Bundle 和单独输出的静态资源。开发构建会保留脚本、样式和调试元数据等中间产物，便于检查构建结果。目录结构、文件命名和输出路径的配置见[构建输出文件](./output.mdx)。

### 跨应用共享代码 {#external-bundles}

多个应用可以从 External Bundle 加载公共依赖，减少各自重复打包的内容。它与应用内的[代码分割](/react/code-splitting.md)解决不同的复用需求。[External Bundle](./external-bundle.mdx)介绍如何构建共享 Bundle，以及如何在宿主应用中加载它。

## 扩展构建流程 {#plugins}

Lynx 构建可以组合 Rsbuild 插件，例如预处理器、类型检查和资源优化插件；需要更底层的扩展时，也可以通过 [`tools.rspack`](https://rsbuild.rs/zh/config/tools/rspack) 接入 Rspack 插件。通用扩展方式见 [Rsbuild 插件文档](https://rsbuild.rs/zh/plugins/list/)，Lynx 自身的插件从 [`pluginLynx`] 所在的包开始，列在 API 参考的“插件与工具”中。

## 调试与性能分析 {#debugging-and-profiling}

构建阶段，可以通过 [Rsdoctor 和构建性能分析](https://rsbuild.rs/zh/guide/debug/build-profiling)了解耗时和依赖关系。应用运行后，[框架性能分析](/guide/performance/analysis-performance/analysis-framework.mdx)和[产物体积分析](/guide/performance/analysis-performance/analysis-bundle-size.mdx)帮助你定位性能与体积问题。

构建生成的调试元数据还能用于[反解线上错误](/guide/devtool/map-errors-to-source.mdx)，[UI Source Map](/guide/devtool/ui-source-map.mdx)则将运行中的节点映射回创建它的 JSX。这些能力把构建产物与源码关联起来，供开发和线上排查使用。
