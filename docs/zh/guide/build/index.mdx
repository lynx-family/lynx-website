# 构建与交付 Bundle

这一节讲 Lynx 应用怎么构建和交付：用什么工具构建、产出什么，以及怎么保证它能在目标 Lynx Engine 上运行。

- [Lynx Bundle 与兼容性](./lynx-bundle.mdx)：构建产出什么、能在哪些引擎上运行
- [构建输出文件](./output.mdx)：文件落在哪里
- [Rspeedy](./rspeedy.mdx)：同一套引擎的早期命令行封装，以及如何迁出

## 用什么构建 {#tools}

Lynx 应用由 [Rsbuild](https://rsbuild.rs/) 构建。让产物成为 Lynx Bundle 而不是 Web Bundle 的，是 [**`pluginLynx`**](/api/packages/rsbuild-plugin)——以一组 Rsbuild 插件形式提供的 Lynx 构建引擎。

运行这套引擎有两种方式：

- **Rsbuild + `pluginLynx`**：推荐方式。你维护一份普通的 `rsbuild.config.ts`，用 `rsbuild` 命令行。
- **Rspeedy**：同一套引擎的封装，提供自己的 `rspeedy` 命令行和 `lynx.config.ts`。

```bash
# Rsbuild + pluginLynx（推荐）
npm create @lynx-js/lynx@latest -- --template rsbuild-react-ts

# Rspeedy
npm create @lynx-js/lynx@latest -- --template rspeedy-react-ts
```

两者产出的 `.lynx.bundle` 完全相同，dev server、HMR、二维码、debug metadata 的行为也一致——这些都在 `pluginLynx` 里。区别在于命令行由谁提供，以及你能触及多少 Rsbuild 的配置能力。

### Rsbuild + pluginLynx

`pluginLynx`（来自 [`@lynx-js/rsbuild-plugin`](https://www.npmjs.com/package/@lynx-js/rsbuild-plugin)）是把一次 Rsbuild 构建变成 Lynx 构建的关键。它配置双线程产物与 Bundle 文件名，把中间产物保留在 `dist/.lynx/<entry>/`，按 Lynx 运行时调整压缩与 source map，按 Lynx 的 `exports` 条件解析模块，在开发时通过局域网把产物推送到设备，并注册[线上错误反解](/guide/devtool/map-errors-to-source.mdx)所需的 debug metadata。

你很少需要手动引入它：[`pluginReactLynx`](/api/packages/react-rsbuild-plugin/functions/pluginReactLynx) 在它尚未注册时会自动应用，所以 ReactLynx 模板的配置里只写了 `pluginReactLynx`。

```ts title="rsbuild.config.ts"
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';
import { defineConfig } from '@rsbuild/core';

export default defineConfig({
  source: {
    entry: {
      main: './src/index.tsx',
    },
  },
  plugins: [pluginReactLynx()],
});
```

两点需要注意：

- **[`source.entry`](https://rsbuild.rs/config/source/entry) 用对象形式**，和其他 Rsbuild 项目一致。
- **需要配置选项时要自己引入 `pluginLynx`。** 自动应用用的是默认选项，所以想配 [`output.filename.bundle`](/api/build/output/filename/bundle) 或 [`performance.profile`](/api/build/performance/profile)，需要在 `plugins` 里显式写上 `pluginLynx({ ... })`，不会重复应用。

`pluginLynx` 新增的配置项，以及它为 Lynx 改了默认值的 Rsbuild 配置项，见[构建配置参考](/api/build)。

类型声明来自 Rsbuild：

```json title="tsconfig.json"
{
  "compilerOptions": {
    "types": ["@rsbuild/core/types"]
  }
}
```

### Rspeedy

Rspeedy 用自己的 `rspeedy` 命令行和 `lynx.config.ts` 封装了同一套引擎，详见 [Rspeedy](./rspeedy.mdx)。

### 该用哪个

新项目用 **Rsbuild + `pluginLynx`**。这是 [`@lynx-js/create-lynx`](https://www.npmjs.com/package/@lynx-js/create-lynx) 推荐的方式，配置和命令行都与 Rstack 生态的文档一致，Rsbuild 的完整配置能力和插件生态都可以直接使用。

Rspeedy 仍在维护。现有项目如果依赖 `rspeedy` 命令行或 `lynx.config.ts`，不必急着迁；新项目就别从它开始了。

不带 `--template` 执行 `npm create @lynx-js/lynx@latest` 会让你选择构建工具，也提供用于组件库的 Rslib。

迁移现有项目见[迁移现有的 Rspeedy 项目](./rspeedy.mdx#migrating-an-rspeedy-project)。
