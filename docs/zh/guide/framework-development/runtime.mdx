# 运行时模型

Lynx 提供主线程和后台线程两个相互独立的 JavaScript 执行环境。每个框架都需要主线程渲染入口，用于处理引擎生命周期并驱动 UI。
在此基础上，框架可以在主线程中处理轻量状态与同步更新，也可以按需引入后台线程，分担状态管理、更新调度、异步任务和业务计算。
后台线程不能替代主线程，状态变化最终仍由主线程落实为 UI 更新。

## 构建主线程渲染入口

无论是否引入后台线程，主线程都需要处理引擎生命周期、持有后续更新需要的节点引用，并将状态变化转换为 Element PAPI 操作。

### 响应主线程生命周期事件

`lynx.getEngine()` 仅用于监听 Lynx 引擎定义的生命周期事件。这些事件构成页面 UI 的渲染、更新和销毁入口：

| 事件                | UI 生命周期阶段 | 框架需要完成的工作                                                                              |
| ------------------- | --------------- | ----------------------------------------------------------------------------------------------- |
| `__RenderPage`      | 渲染            | 处理首屏数据，将状态转换为 Element PAPI 操作并创建初始元素树。首次渲染使用 SDK 的默认提交时机。 |
| `__UpdatePage`      | 更新            | 消费宿主后续数据，确定状态变化，更新元素树并调用 `__FlushElementTree()` 提交 UI。               |
| `__DestroyLifetime` | 销毁            | 移除引擎与节点监听器、释放本地引用；使用后台线程时同步转发销毁事件。                            |

下面的示例代码展示主线程如何注册这三个入口：

```ts title="main-thread.ts" {2-5}
// 注册页面渲染、更新和销毁回调
const engine = lynx.getEngine();
engine.addEventListener('__RenderPage', onRenderPage);
engine.addEventListener('__UpdatePage', onUpdatePage);
engine.addEventListener('__DestroyLifetime', onDestroyLifetime);

function onRenderPage(event) {
  const [data] = event.data;
  renderPage(data);
}
function onUpdatePage(event) {
  const [data] = event.data;
  updatePage(data);
}
function onDestroyLifetime() {
  clearPage();
}
```

其中，`renderPage` 和 `updatePage` 主要用于接收数据，并基于 [Element PAPI](/api/engine/element-api) 构造和更新 UI。

```ts title="main-thread.ts" {6-11,16-17}
const page = __CreatePage('0', 0);
const pageId = __GetElementUniqueID(page);
let titleText;

function renderPage(data) {
  const container = __CreateView(pageId);
  const title = __CreateText(pageId);
  titleText = __CreateRawText(data.title);
  __AppendElement(title, titleText);
  __AppendElement(container, title);
  __AppendElement(page, container);
}

function updatePage(data) {
  if (data.title) {
    __SetAttribute(titleText, 'text', data.title);
    __FlushElementTree();
  }
}
```

`clearPage` 则负责解除页面生命周期内注册的所有事件监听器，并释放保存的 Element 节点引用、元素映射和状态数据。

```ts title="main-thread.ts"
function clearPage() {
  engine.removeEventListener('__RenderPage', onRenderPage);
  engine.removeEventListener('__UpdatePage', onUpdatePage);
  engine.removeEventListener('__DestroyLifetime', onDestroyLifetime);
  titleText = null;
}
```

### 处理轻量交互逻辑

节点事件可以通过 `__AddEventListener()` 直接在主线程注册。下面的代码模拟一个极简框架：

```ts title="main-thread.ts" {2-9,18-25}
// 框架内部维护状态，并在状态变化时驱动一次更新。
function useState(initialValue) {
  let value = initialValue;
  const setValue = function (nextValue) {
    value = nextValue;
    updatePage({ title: value });
  };
  return [value, setValue];
}

function renderPage(data) {
  const [title, setTitle] = useState(data.title);

  const titleElement = __CreateText(pageId);
  titleText = __CreateRawText(title);

  // 事件回调通过框架状态 setter 发起更新。
  __AddEventListener(
    titleElement,
    'tap',
    function () {
      setTitle('Hello Lynx');
    },
    tapEventOptions,
  );
}
```

对于不依赖异步任务和复杂调度的计数、显隐切换等轻量交互，框架可以在主线程完成“更新状态 → 修改 Element 节点 → 提交 UI”的闭环。

## 按需引入后台线程

当更新链路涉及异步任务、复杂调度或较重计算时，可以按需引入后台线程，将这些适合脱离 UI 的逻辑放在后台执行。

### 通过配对上下文通信

主线程和后台线程通过 `lynx.getJSContext()` 与 `lynx.getCoreContext()` 返回的配对端点交换事件。
一个端点派发的事件，会由另一个线程中与之配对的端点接收：

| 方向              | 发送端                             | 接收端                             |
| ----------------- | ---------------------------------- | ---------------------------------- |
| 主线程 → 后台线程 | 主线程的 `lynx.getJSContext()`     | 后台线程的 `lynx.getCoreContext()` |
| 后台线程 → 主线程 | 后台线程的 `lynx.getCoreContext()` | 主线程的 `lynx.getJSContext()`     |

跨线程通信应缓存并复用上述端点，通过 `dispatchEvent()` 发送事件、通过 `addEventListener()` 接收事件；
销毁时使用相同的端点、事件名和函数引用移除监听器。
事件载荷应保持小且可序列化，只传递基本类型、数组和普通对象。

### 跨线程状态更新

前面的轻量示例中，`setTitle()` 在主线程直接更新 UI。引入后台线程后，这次状态变更将在两个线程间依次流转：

1. 后台线程维护状态和框架更新逻辑

```ts title="background.ts" {1,6-8}
const [title, setTitle] = useState('Hello World');

function useState() {
  let value = initialValue;
  const setValue = function (id, nextValue) {
    value = nextValue;
    // 框架需要完成的工作
    handleUpdate(id);
  };
  return [value, setValue];
}
```

2. 主线程将更新任务转发给后台线程

```ts title="main-thread.ts" {6-9}
const elementMap = new Map();
const backgroundThread = lynx.getJSContext();
function setTitle(element, title) {
  const elementId = __GetElementUniqueID(element);
  elementMap.set(elementId, element);
  backgroundThread.dispatchEvent({
    type: 'SetTitle',
    data: { id: elementId, value: title },
  });
}

function renderPage(data) {
  const titleElement = __CreateText(pageId);
  const titleText = __CreateRawText(data.title);
  __AddEventListener(
    titleElement,
    'tap',
    function () {
      setTitle(titleText, 'Hello Lynx');
    },
    tapEventOptions,
  );
}
```

3. 后台线程响应更新事件

```ts title="background.ts" {2,6}
const mainThread = lynx.getCoreContext();
mainThread.addEventListener('SetTitle', onSetTitle);

function onSetTitle(event) {
  const { id, value } = event.data;
  setTitle(id, value);
}
```

4. 后台线程的框架驱动根据最新状态生成 patch，并发送给主线程

```ts title="background.ts" {4}
const mainThread = lynx.getCoreContext();
function handleUpdate(id) {
  // 经过框架计算后获取，这里只是一个简单的例子
  const patch = [['__SetAttribute', id, 'text', 'Hello Lynx']];
  mainThread.dispatchEvent({
    type: 'Patch',
    data: patch,
  });
}
```

5. 主线程消费补丁，调用 Element PAPI 更新 UI

```ts title="main-thread.ts" {11}
const backgroundThread = lynx.getJSContext();
backgroundThread.addEventListener('Patch', onPatch);

function onPatch(event) {
  const { patch } = event.data;
  for (let item of patch) {
    const [action, id, key, value] = item;
    const element = elementMap.get(id);
    switch (action) {
      case '__SetAttribute':
        __SetAttribute(element, key, value);
        break;
      default:
        break;
    }
  }

  __FlushElementTree();
}
```
