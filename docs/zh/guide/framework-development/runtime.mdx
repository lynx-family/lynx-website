# 运行时模型

Lynx 框架的运行时从主线程入口开始。主线程响应引擎生命周期，持有 Element 节点，并将状态变化落实为 UI 更新。
在这条必需链路之上，框架可以直接处理轻量交互，也可以按需引入后台线程，分担状态管理、更新调度、异步任务和业务计算。

本文先构建一个仅使用主线程的最小运行时，再沿一次用户交互逐步加入后台线程：

<Mermaid>{`
flowchart LR
  Data["宿主数据"] --> Lifecycle["主线程生命周期"]
  Lifecycle --> Element["Element PAPI"]
  Element --> UI["UI"]
  UI --> Event["用户交互"]
  Event --> MainUpdate["主线程更新处理"]
  MainUpdate --> Element
  Event -. "按需转发" .-> Background["后台线程任务与状态"]
  Background -. "数据或 Patch" .-> MainUpdate
`}</Mermaid>

## 从主线程入口开始

无论是否引入后台线程，框架都要先在主线程建立“接收数据 → 更新 Element 树 → 提交 UI”的闭环。第一步是接入页面生命周期。

### 接入页面生命周期

框架通过 `lynx.getEngine()` 监听 Lynx 引擎定义的生命周期事件，并将它们转换为自身的渲染、更新和销毁入口：

| 事件                | UI 生命周期阶段 | 框架需要完成的工作                                                                              |
| ------------------- | --------------- | ----------------------------------------------------------------------------------------------- |
| `__RenderPage`      | 渲染            | 处理首屏数据，将状态转换为 Element PAPI 操作并创建初始元素树。首次渲染使用 SDK 的默认提交时机。 |
| `__UpdatePage`      | 更新            | 消费宿主后续数据，确定状态变化，更新元素树并调用 `__FlushElementTree()` 提交 UI。               |
| `__DestroyLifetime` | 销毁            | 移除引擎与节点监听器、释放本地引用；使用后台线程时同步转发销毁事件。                            |

`clearPage` 负责解除页面生命周期内注册的监听器，并释放节点引用、元素映射和状态数据：

## 按需引入后台线程

后台线程是主线程模型之上的可选扩展。它不持有 Element 节点，也不能替代主线程，而是负责计算新的状态或数据补丁，再交由主线程更新 UI。

### 建立配对通信通道

主线程和后台线程通过 `lynx.getJSContext()` 与 `lynx.getCoreContext()` 返回的配对端点交换事件。
一个端点派发的事件，会由另一个线程中与之配对的端点接收：

| 方向              | 发送端                             | 接收端                             |
| ----------------- | ---------------------------------- | ---------------------------------- |
| 主线程 → 后台线程 | 主线程的 `lynx.getJSContext()`     | 后台线程的 `lynx.getCoreContext()` |
| 后台线程 → 主线程 | 后台线程的 `lynx.getCoreContext()` | 主线程的 `lynx.getJSContext()`     |

跨线程通信应缓存并复用上述端点，通过 `dispatchEvent()` 发送事件、通过 `addEventListener()` 接收事件；
销毁时使用相同的端点、事件名和函数引用移除监听器。
事件载荷应保持小且可序列化，只传递基本类型、数组和普通对象。

通信通道建立后，框架还需要定义更新协议：主线程发送任务，后台线程更新状态并生成 Patch，最后由主线程应用 Patch。

### 串联一次跨线程更新

下面沿一次点击更新，按搭建顺序串联两个线程：

<Mermaid>{`
sequenceDiagram
  participant Main as 主线程
  participant Background as 后台线程
  Main->>Background: SetTitle { id, value }
  Background->>Background: 更新状态并生成 Patch
  Background->>Main: Patch [...]
  Main->>Main: Element PAPI + Flush
`}</Mermaid>

前面的轻量示例中，`setTitle()` 在主线程直接更新 UI。引入后台线程后，这次状态变更依次经过以下步骤。

框架状态在后台线程中声明并维护，与主线程持有的 Element 节点分离，`setValue` 提供统一的数据更新能力。
