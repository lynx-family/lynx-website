# 构建产物

运行时确定了主线程如何驱动 UI，以及框架逻辑是否需要后台线程。
构建阶段的任务是将这些输入交付为宿主可加载的 Lynx Bundle。

## 构建目标：一个入口，一个 Bundle

一个逻辑入口在构建内部可以形成以下处理路径：

| 处理路径       | 是否必需 | 作用                                                 |
| -------------- | -------- | ---------------------------------------------------- |
| 主线程 layer   | 是       | 提供页面渲染入口，运行 Element PAPI 和 UI 更新逻辑。 |
| 后台线程 layer | 否       | 承载按需拆分出的状态管理、调度、异步或较重计算。     |
| 样式 loader    | 否       | 将样式资源处理为页面和 Element 节点的样式资产。      |

构建器从同一个逻辑入口建立主线程 layer，并按需派生后台线程 layer。两个 layer 中的资源分别经过匹配的 loader 处理，形成对应的线程资产；样式资源则由样式 loader 处理。三类资产最终作为同一入口的组成部分组装并编码到最终产物中：

<Mermaid>{`

  Entry["逻辑入口"] --> MainLayer["主线程 layer（必需）"]
  Entry --> BackgroundLayer["后台线程 layer（可选）"]
  Entry --> StyleLoader["样式 loader（可选）"]:::flow-label
  MainLayer --> MainLoader["loader 处理"]:::flow-label --> MainAsset["主线程资产"]
  BackgroundLayer --> BackgroundLoader["loader 处理"]:::flow-label --> BackgroundAsset["后台线程资产"]
  StyleLoader --> StyleAsset["样式资产"]
  MainAsset --> Assemble["组装与编码"]
  BackgroundAsset --> Assemble
  StyleAsset --> Assemble
  Assemble --> Bundle["demo.lynx.bundle"]
`}</Mermaid>

Rspeedy 默认输出通常为 `[name].lynx.bundle`，也可以通过构建配置修改。
仅包含轻量 UI 交互的入口可以只建立主线程 layer；不需要为了构建一致性创建空的后台线程 layer。

## 构建双线程 layer

`layer` 用于在同一次构建中区分模块的线程归属，是构建期的编译上下文，不代表额外创建了运行时线程。
Rsbuild 的 [`source.entry` 描述对象](https://rsbuild.rs/zh/config/source/entry)可以承载 entry 的 `layer` 信息。
构建器以逻辑入口为单位，将其展开为主线程 layer 和可选的后台线程 layer：

```ts title="thread-layers.ts"
import type { RsbuildPlugin } from '@rsbuild/core';

const LAYERS = {
  MAIN_THREAD: 'framework:main-thread',
  BACKGROUND: 'framework:background',
} as const;

export const pluginThreadLayers: RsbuildPlugin = {
  name: 'framework:thread-layers',
  setup(api) {
    api.modifyBundlerChain((chain) => {
      const entryName = 'app';
      const imports = ['./src/page-entry'];

      // 将一个逻辑入口展开为构建器内部使用的线程入口。
      chain.entryPoints.clear();
      chain.entry(`${entryName}__main-thread`).add({
        import: imports,
        layer: LAYERS.MAIN_THREAD,
        filename: `.rspeedy/${entryName}/main-thread.js`,
      });

      // 不需要后台线程时，省略这个内部入口。
      chain.entry(`${entryName}__background`).add({
        import: imports,
        layer: LAYERS.BACKGROUND,
        filename: `.rspeedy/${entryName}/background.js`,
      });
    });
  },
};
```

示例让两个 layer 复用同一组入口资源。框架也可以为后台线程传入独立资源；不需要后台线程时，则不创建对应的内部入口。entry 上的 `layer` 会沿模块图传递，loader 规则可以通过 `issuerLayer` 选择线程对应的转换流程。

| 构建步骤    | 处理方式                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 展开入口    | 为同一个逻辑入口创建主线程内部入口，并按需创建后台线程内部入口；两者使用不同的 layer。                                        |
| 路由 loader | 根据 `issuerLayer` 或等价信息选择线程对应的 loader 链。同一种资源可以在不同 layer 中执行不同转换，资源类型不由线程入口限定。  |
| 生成资产    | 将主线程 layer 和存在的后台线程 layer 分别输出为对应资产；主线程资产需要携带 `lynx:main-thread` 标记，供后续组装阶段识别。    |
| 处理样式    | 样式不构成第三个线程 layer，而是由样式 loader 生成独立的样式资产，并与当前逻辑入口关联。构建器应避免两个 layer 重复提取样式。 |

两个 layer 可以复用同一组入口依赖，也可以分别指向不同资源。框架可以据此选择“同一份源码按线程分别转换”或“为两个线程提供独立实现”；后续组装只依赖资产的线程角色，不依赖源码的组织方式。

主线程 layer 必须存在，因为它提供驱动 UI 的入口。后台线程 layer 按需引入，用于承载状态管理、任务调度、异步工作或较重计算。后台线程是否存在，应由框架的运行时模型决定，而不是由构建器自动补充空入口。

## 编码为 Bundle

线程和样式完成编译后，构建器以逻辑入口声明的 chunk 集合为边界收集资产，并按以下结构准备编码输入：

| 编码输入     | 内容                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| 主线程代码   | 从带有 `lynx:main-thread` 标记的资产中取得，作为 Bundle 的主线程区段。                 |
| 后台线程代码 | 由其余后台 JavaScript 资产组成，并以模块清单记录文件名和内容；没有后台线程时可以为空。 |
| 样式数据     | 将关联的 CSS 资产序列化为编码器需要的规则映射和样式内容。                              |
| 编译元数据   | 包含 DSL、目标 Engine 版本、编译开关、页面类型以及框架需要写入的其他配置。             |
| 自定义区段   | 按需携带延迟加载组件、字节码或其他扩展数据；不需要扩展能力时保持为空。                 |

在原生目标上，后台线程资产的运行时包装发生在 encode 之前，主线程资产不经过这一步。构建器还需要根据分包策略决定后台脚本是内联到 Bundle，还是在模块清单中保留外部 chunk 的加载信息；无论采用哪种方式，宿主加载的页面入口仍然是最终 Bundle。

编码器将上述结构化数据转换为 Lynx 模板二进制，并生成调试信息和样式诊断。构建器随后根据当前逻辑入口解析输出文件名，写出 `[name].lynx.bundle`。开发或诊断构建可以保留主线程、后台线程、CSS 和编码参数等中间产物；生产构建则可以移除已经内联到 Bundle 的中间资产。

encode 不是把主线程 JavaScript、后台线程 JavaScript 和 CSS 直接拼接到一个文件中，而是先明确各类资产在模板中的角色，再由编码器写入对应区段。自定义框架需要保持的核心契约是：一个逻辑入口对应一组有明确角色的资产，并最终编码为一个可由宿主加载的 Bundle。
