# 从 DSL 到 Bundle

[运行时模型](/guide/framework-development/runtime)说明主线程如何驱动 UI、后台线程如何参与更新；[Bundle 构建](/guide/framework-development/build)说明这些代码如何成为一个 Lynx 产物。本教程以教学 DSL `Greeting.lynx` 为输入，串联两者之间的框架编译流程。

`Greeting.lynx` 不是 Lynx 内置文件格式，而是用于说明编译器职责的最小示例。真实框架可以选择自己的语法、文件后缀和编译器实现。

## 1. 用 DSL 描述页面与更新意图

下面的 DSL 声明一个标题。点击标题会运行异步任务 `refreshGreeting`，任务取得新标题后写回 `title`：

```text title="src/Greeting.lynx"
screen Greeting {
  state title = "Hello World"

  text #title {
    value = title
    on tap {
      run refreshGreeting
    }
  }

  task refreshGreeting {
    title <- await fetchGreeting()
  }

  style #title {
    font-size: 32px
    color: #222222
  }
}
```

框架编译器先将源文件解析为中间表示，再决定每个声明生成到哪个线程。这个例子中，异步任务需要后台线程，因此生成计划如下：

| DSL 声明   | 生成位置   | 生成职责                                                |
| ---------- | ---------- | ------------------------------------------------------- |
| `text`     | 主线程     | 创建 Element 树、绑定点击事件、应用后台返回的操作列表。 |
| `state`    | 后台线程   | 保存状态，并在状态变化后触发框架更新。                  |
| `task`     | 后台线程   | 执行异步任务，将结果写入状态。                          |
| `run task` | 两个线程间 | 将主线程交互转换为后台线程可处理的任务消息。            |
| `style`    | 样式产物   | 输出与 `#title` 对应的样式规则。                        |

对应的中间表示可以足够简单：

```ts title="Greeting.lynx 的中间表示"
{
  state: { title: 'Hello World' },
  nodes: [{ id: 'title', type: 'text', value: 'title' }],
  events: [{ node: 'title', name: 'tap', run: 'refreshGreeting' }],
  tasks: [{ name: 'refreshGreeting', async: true, writes: ['title'] }],
}
```

其中 `#title` 是主线程节点标识，`value = title` 是状态绑定，`run refreshGreeting` 是跨线程任务意图。编译器据此生成下面三个文件。

## 2. 生成双线程运行时入口

页面生命周期、线程通信端点和资源释放由框架运行时处理，具体约定见[运行时模型](/guide/framework-development/runtime)。这里仅展示由 DSL 直接生成的页面逻辑：主线程先创建 UI 并接收 patch，后台线程维护状态并产生 patch。

### 生成主线程入口

`text #title` 与 `on tap` 生成到 `main-thread.ts`。框架运行时会在首屏时调用 `renderGreeting()`；首次渲染使用 SDK 的默认提交时机，后续 patch 才显式调用 `__FlushElementTree()`。

```ts title=".framework/greeting/main-thread.ts"
const page = __CreatePage('0', 0);
const pageId = __GetElementUniqueID(page);
const backgroundThread = lynx.getJSContext();
const elementMap = new Map();

function renderGreeting() {
  const title = __CreateText(pageId);
  const titleText = __CreateRawText('Hello World');
  __SetID(title, 'title');
  elementMap.set('title', titleText);

  __AddEventListener(title, 'tap', onTitleTap, {});
  __AppendElement(title, titleText);
  __AppendElement(page, title);
}

function onTitleTap() {
  backgroundThread.dispatchEvent({
    type: 'Intent',
    data: { type: 'run', task: 'refreshGreeting' },
  });
}

function onPatch(event) {
  // event.data 是后台线程发送的可序列化操作列表。
  for (const [action, id, key, value] of event.data) {
    const element = elementMap.get(id);
    if (action === '__SetAttribute' && element) {
      __SetAttribute(element, key, value);
    }
  }

  __FlushElementTree();
}

backgroundThread.addEventListener('Patch', onPatch);
```

主线程保存 Element 节点引用；跨线程传递的仅是节点标识与操作参数，不传递节点本身。

### 生成后台线程入口

`state title` 与 `task refreshGreeting` 生成到 `background.ts`。任务只更新状态，框架运行时负责根据状态变化生成操作列表并发送回主线程：

```ts title=".framework/greeting/background.ts"
const mainThread = lynx.getCoreContext();
let state = { title: 'Hello World' };

function setTitle(title: string) {
  if (title === state.title) return;

  state = { ...state, title };
  flushUpdate();
}

function flushUpdate() {
  const patch = [['__SetAttribute', 'title', 'text', state.title]];
  mainThread.dispatchEvent({
    type: 'Patch',
    data: patch,
  });
}

async function refreshGreeting() {
  setTitle(await fetchGreeting());
}

function onIntent(event) {
  const intent = event.data;
  if (intent?.type === 'run' && intent.task === 'refreshGreeting') {
    void refreshGreeting();
  }
}

mainThread.addEventListener('Intent', onIntent);
```

这次交互的更新路径为：

1. 主线程将点击转换为 `Intent` 消息。
2. 后台线程执行 `refreshGreeting()`，更新状态并生成可序列化的 Element PAPI 操作列表。
3. 主线程消费 `Patch`，定位节点、执行操作并提交 UI。

跨线程事件名、端点配对和销毁时的监听器释放，沿用[运行时模型中的通信约定](/guide/framework-development/runtime#建立配对通信通道)。

## 3. 将 DSL 编译器接入 Rsbuild

编译器本身可以封装为 Rsbuild 插件。它从 Rspeedy 的 `source.entry` 读取 `.lynx` 输入，将逻辑入口替换为生成的主线程、后台线程和样式入口。
开发模式还需要监听源文件变化并重新生成这些入口，以下示例省略监听实现：

```ts title="framework/plugin-my-lynx.ts"
import type { RsbuildPlugin } from '@rsbuild/core';

export function pluginMyLynx(): RsbuildPlugin {
  return {
    name: 'framework:my-lynx',
    setup(api) {
      api.modifyBundlerChain((chain) => {
        // `source.entry` 中的 app: './src/Greeting.lynx'。
        const entries = chain.entryPoints.entries() ?? {};

        for (const [entryName, entry] of Object.entries(entries)) {
          const [input] = getEntryImports(entry.values());
          const component = parseLynxFile(input);

          // 框架内部创建生成模块，并注册为双线程与样式入口。
          replaceWithGeneratedEntries(chain, entryName, {
            mainThread: generateMainThread(component),
            background: generateBackground(component),
            style: generateStyles(component),
          });
        }
      });
    },
  };
}
```

配置中仍以开发者编写的 `.lynx` 文件作为逻辑入口。DSL 插件在构建过程中将它展开为主线程、后台线程与样式入口；框架的 Bundle 插件再完成资产分组和编码：

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy';
import { pluginMyLynx } from './framework/plugin-my-lynx';
import { pluginFrameworkBundle } from './framework/plugin-lynx-bundle';

export default defineConfig({
  source: {
    entry: {
      app: './src/Greeting.lynx',
    },
  },
  output: {
    filename: {
      bundle: '[name].lynx.bundle',
    },
  },
  plugins: [pluginMyLynx(), pluginFrameworkBundle()],
});
```

`source.entry` 是 DSL 编译器的输入，`output.filename.bundle` 决定最终 Bundle 的文件名。`pluginFrameworkBundle()` 负责将生成的双线程资产交给 `LynxTemplatePlugin` 和 `LynxEncodePlugin`；资产标记、后台包装与编码输入的组装方式，见[Bundle 构建](/guide/framework-development/build)。

## 4. 从源文件交付到 Lynx 产物

至此，框架完成了从 DSL 到 Lynx Bundle 的完整链路：

```text
Greeting.lynx
  └─→ DSL 编译器
        ├─→ main-thread.ts
        ├─→ background.ts
        └─→ style.css
              └─→ 框架 Bundle 插件
                    └─→ app.lynx.bundle
```

DSL 编译器决定如何把状态、事件和样式转换为双线程入口；框架运行时负责在这些入口中执行渲染与更新；构建插件则将线程资产编码为可加载的 Bundle。
更改语法、状态模型或更新策略时，可以保持这三层职责不变，只替换对应框架实现。

如需回顾具体约定，请继续参阅[运行时模型](/guide/framework-development/runtime)和[Bundle 构建](/guide/framework-development/build)。
