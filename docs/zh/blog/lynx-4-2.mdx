**Lynx 4.2 已经正式发布！**由于 Lynx 4.1 与 4.2 的发布时间间隔较短，我们不再为 4.1 单独编写 release blog。这篇文章将一并介绍 [Lynx 4.0](/blog/lynx-4-0) 之后，**两个版本**的重要更新。

这一轮更新的关键词是“可控”：通过 CSS Layer 组织样式优先级，根据样式能力与动态颜色偏好应用不同规则，自主决定 ReactLynx 首屏同步时机，以及沿着页面生命周期分析内存。同时，图片、文本、滚动交互和宿主接入也有进一步完善。

## 更可预测的 CSS 行为

### 通过 `@layer` 组织样式

随着设计系统不断扩展，覆盖组件样式很容易变成不断堆叠选择器优先级的竞争。CSS `@layer` 允许你先确定各组样式的顺序，而不必为每次覆盖寻找更复杂的选择器。

例如，下面的卡片会保留 `components` 层的背景色，并采用 `utilities` 层定义的内边距：

```css
@layer reset, base, components, utilities;

@layer components {
  .card {
    padding: 16px;
    background-color: #e8f4ff;
  }
}

@layer utilities {
  .compact {
    padding: 8px;
  }
}
```

```tsx
<view className="card compact">
  <text>A compact card with 8px padding</text>
</view>
```

普通声明中靠后的层优先于靠前的层；同一层内仍由选择器优先级和源码顺序决定。未放入任何层的普通声明优先于层内声明。

`@layer` 和下文的 `@supports` 支持需要在构建时启用 CSS Rule。请在现有构建配置的插件列表中，与项目使用的 Lynx 和 ReactLynx 插件一起添加以下插件：

```js
import { pluginLynxConfig } from '@lynx-js/config-rsbuild-plugin';

pluginLynxConfig({
  enableCSSRule: true,
});
```

具体配置可参考 [CSS Rule 配置示例](/api/css/media-query#启用-css-rule-编码)。

### 按条件应用样式

现在可以使用 `@supports` 检测 CSS 声明支持、引擎版本范围等条件，并通过 `not`、`and`、`or` 进行条件组合。

例如，在支持该声明的运行时中，`.tiles` 的两个子元素会采用两列 grid 布局，而不是纵向 flex 堆叠：

```css
.tiles {
  display: flex;
  flex-direction: column;
}

@supports (display: grid) {
  .tiles {
    display: grid;
    grid-template-columns: 1fr 1fr;
  }
}
```

### 更接近 Web 的布局默认行为

当 `targetSdkVersion >= 4.1` 时，有以下两项默认行为变化，这些能力此前已通过配置引入，本次仅调整默认值：

- 默认启用网格定位简写（`grid-column` 和 `grid-row`）。
- 在 `flex` 简写省略 basis 时使用 `0%`。

:::tip
显式将 `enableGridPlacementShorthands` 或 `enableFlexBasisZeroPercent` 设置为 `false`，仍可覆盖默认行为。

升级 SDK 版本时，请检查依赖网格定位，或依赖零长度与百分比 flex basis 差异的布局。
:::

## 文本与滚动交互

### 精细控制文本装饰

在 **Android** 和 **iOS** 中现在可以使用以下三个属性让文本装饰样式更加可控：

- `text-decoration-thickness` 控制装饰线厚度。
- `-x-text-decoration-width` 控制虚线线段长度或波浪线的周期宽度。
- `-x-text-decoration-gap` 控制虚线或点线的间距。

可以从现有的文本装饰示例开始：

```css

  text-decoration-style: dashed;
  text-decoration-color: #1479ff;
  text-decoration-thickness: 2px;
  -x-text-decoration-width: 8px;
  -x-text-decoration-gap: 4px;
}
```

### 一次滑动跨越更多列表项

吸附列表不必在每次手势后只前进一项。Android 和 iOS 的 `item-snap` 新增 `maxSnapCount`，允许一次快速滑动跨越多个列表项。默认值仍为 `1`，保持原有行为。

先来看现有的横向吸附示例：

`<scroll-view>` 也新增了按项吸附能力，为分页滚动提供另一种选择。

## ReactLynx

### 自主决定首屏就绪时机

[首帧直出](/guide/interaction/ifr)允许主线程在后台运行时就绪之前完成渲染。对于关键数据分批到达的页面，ReactLynx 现在允许开发者明确决定何时将首屏节点树同步到后台线程：

```js
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';

pluginReactLynx({
  firstScreenSyncTiming: 'manual',
});
```

当页面所需的首屏关键数据准备完成后，调用[就绪 API](/api/react/Functions/markFirstScreenSyncReady)：

```ts
import { markFirstScreenSyncReady } from '@lynx-js/react';

// Call from the application's first-screen data-ready path.
markFirstScreenSyncReady();
```

同步之前，主线程仍可同步处理宿主的 `updateData` 调用。只有已发送就绪信号，**且**当前首屏渲染完成后，才会执行同步。该 API 可以在任一线程调用，重复调用不会产生额外效果。

:::warning 务必发送就绪信号

手动模式下，数据就绪路径必须调用 `markFirstScreenSyncReady()`，也需要覆盖预期的数据请求失败回退路径。否则，后台线程的 hydration 以及依赖它的事件处理将始终不可用。不要等待这类事件处理函数来发送首次就绪信号。

:::

## 其他 API 更新

其他涉及 API 的主要更新有：

- **SVG 图片服务扩展。**图片服务接口新增 [Android `fetchSVGImage`](https://github.com/lynx-family/lynx/pull/8104) 和 [iOS `loadSVGImageWithURL`](https://github.com/lynx-family/lynx/pull/8184) 扩展点，供接入图片服务使用。
- **逻辑元素树查询。**Android、iOS 和 HarmonyOS 新增 LynxElement 节点查询与父子关系访问；Android 和 iOS 还可访问对应的平台视图。逻辑元素树与原生视图层级并不等同。
- **TemplateBundle 预加载。**Lynx 4.2 为 Android、iOS 和 HarmonyOS 增加了 [`TemplateBundle.preload`](/api/lynx-native-api/template-bundle.html)，可将模板二进制数据异步加载到预先创建的主线程运行时中，把这部分准备工作前移到页面使用之前。
- **`Promise.allSettled`。**Lynx Promise 新增 `allSettled`，等待所有异步操作结束后，分别处理每项的成功值或失败原因，而不是在首次拒绝时就让整组操作返回失败。
