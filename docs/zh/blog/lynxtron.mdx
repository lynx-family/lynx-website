Lynx 正在走向桌面端。

**Lynxtron** 是由 Lynx 驱动的 Electron-like 应用框架。在 Lynxtron 应用中，宿主进程仍然保留桌面开发需要的 Node.js 能力，而窗口层由 `LynxWindow` 通过轻量 UI 渲染器承载 Lynx UI，而不是加载浏览器页面。

这意味着：你可以用 Lynx 的 UI 模型构建桌面应用，同时继续获得更轻的运行时、更直接的原生扩展能力，以及面向桌面、Web 和移动端的跨平台代码组织方式。

## Lynxtron 解决什么问题

桌面应用开发长期有一个现实选择：要么使用 Web 技术快速构建跨平台应用，要么投入更多原生工程成本换取体积、性能和系统能力。Lynxtron 的目标是在这两者之间提供一个新的路径：用 Lynx 组织 UI，用桌面宿主进程连接系统能力，用原生扩展承载真正需要原生实现的部分。

Lynxtron 围绕 **Light-weight and Fast**、**Multiplatform** 和 **Natively Extensible** 三项特性展开。下面观察它们如何落到桌面应用开发中。

## Light-weight and Fast

Lynxtron 在应用模型上接近 Electron，但它没有把 browser 作为 UI runtime 打包进应用。[`LynxWindow`](/lynxtron/api/@lynx-js/lynxtron/Class.LynxWindow.mdx) 通过轻量化的 Lynx renderer 承载 UI，让桌面运行时更小，也让启动、窗口创建和内存使用路径更直接。

## Natively Extensible

Lynxtron 通过公开的 [extension module C API](https://github.com/lynx-family/lynx/blob/develop/platform/embedder/public/capi/lynx_extension_module_capi.h)、[native view 与 texture surface C API](https://github.com/lynx-family/lynx/blob/develop/platform/embedder/public/capi/lynx_native_view_capi.h) 和 [Node-API](/zh/lynxtron/Native-Libraries/NodeJS-Native-Modules) 扩展渲染器能力。包结构和注册模型请参阅 [Lynx 原生能力库](/zh/lynxtron/Native-Libraries/Lynx-Native-Libraries)。在桌面开发中，一部分图形或 UI 需要原生实现是很常见的需求：摄像头预览、视频画面、地图视图、绘制画布、平台控件，或者任何需要硬件访问、GPU 深度绑定、复用系统渲染能力的 surface。Lynxtron 可以把这些原生 surface 或原生 UI 和 Lynx runtime 结合起来，让需要原生渲染的部分继续走原生路径，同时让交互和界面逻辑继续用 Lynx UI 构建和迭代。

## Multiplatform

Lynxtron 不是把 Lynx 锁在桌面端。借助 Lynx，UI 可以运行在包括 Web 在内的多个平台上，也可以用较低成本迁移到新的宿主环境。

> 同一套 Lynx UI 只依赖统一的 notes API。构建时，桌面和 Web 目标会分别将该 API 接入 Node preload bridge 和浏览器侧 bridge。

这对应的是 Lynxtron 的跨平台工程模型：保持 Lynx UI 层可复用，把平台相关逻辑隔离在宿主适配层中，并在需要时将渲染器模型迁移到新的宿主。

## 工程边界

对开发者来说，更重要的是可检查的源码边界：宿主进程负责桌面能力，Lynx UI 负责界面和交互，原生扩展负责需要平台能力的部分。Lynxtron 的设计重点不是把所有能力收进同一层，而是让每一层承担自己最擅长的职责。
