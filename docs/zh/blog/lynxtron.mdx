桌面应用既需要调用系统能力，也需要快速迭代界面。**[Lynxtron](/zh/lynxtron/)** 保留熟悉的 Node.js 宿主，用 Lynx 渲染应用界面，因此基础运行时无需打包浏览器内核。

<span id="light-weight-and-fast" />

- **下载体积。** [Lynxtron 0.0.28 运行时 ZIP](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) 在 macOS arm64 和 Windows x64 上分别为 **24 MB** 和 **35 MB**；同平台的 [Electron 44.3.0 运行时 ZIP](https://github.com/electron/electron/releases/tag/v44.3.0) 分别为 **130 MB** 和 **158 MB**。
- **启动。** 在抖音 PC 的 Windows 线上实验中，Lynxtron 让首屏展现耗时中位数比对照组缩短 **27%**。实验组内，走 Lynxtron 路径的冷启动首刷 P90 为 **10.8 秒**，常规路径为 **19.0 秒**，相差 **43%**。

## 面向编程智能体的 Electron 风格 API 与架构 \{#multiplatform}

让编程智能体迁移一个 Electron 应用，它可以直接从现有的 Node.js 主进程脚本入手。我们保留了熟悉的生命周期和窗口 API，让智能体可以沿用等待应用就绪、打开窗口等写法。渲染架构则有所变化：Electron 在独立的 Chromium 进程里渲染页面，Lynxtron 在同一进程的主线程上渲染界面，在后台线程执行业务逻辑。[了解 Lynxtron 架构](/zh/lynxtron/learn/what-is-lynxtron)。

![在 Lynxtron 中，Node.js 宿主和 Lynx 渲染共用主线程，UI 业务逻辑运行在后台线程。](https://lf-lynx.tiktok-cdns.com/obj/lynx-artifacts-oss-sg/lynx-website/assets/lynxtron/lynxtron-architecture.png)

例如，Electron 应用通常在 `app.whenReady()` 之后打开第一个窗口。在 Lynxtron 中也一样，创建 `LynxWindow`，然后加载编译好的 Lynx bundle 即可。

```ts
import { app, LynxWindow } from '@lynx-js/lynxtron';

app.whenReady().then(() => {
  const win = new LynxWindow({ width: 800, height: 600 });
  win.show();
  win.loadFile('main.lynx.bundle');
});
```

已有的网页也可以嵌进 Lynx 界面。对于能接受各平台浏览器内核差异的应用，我们计划支持[系统 WebView](https://github.com/lynx-family/lynxtron/issues/395)。现在就需要嵌入网页的应用可以随包分发 [CEF WebView](/zh/lynxtron/api/@lynx-js/cef-webview/index.mdx)，在各平台使用相同的 Chromium 内核。[Lynxtron 0.0.28](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) 的 CEF 独立下载包在 macOS arm64 上为 **126 MB**，在 Windows x64 上为 **161 MB**。

在原生模块接口上，我们沿用了 Electron 的选择：[Node-API](/zh/guide/use-native-modules.html?platform=node-api)。我们的目标是让同一份原生模块实现可以在所有 Lynx 原生平台上复用。[阅读 Node-API 提案](https://github.com/lynx-family/lynx/discussions/845)。
