桌面应用既需要调用系统能力，也需要快速迭代界面。**[Lynxtron](/zh/lynxtron/)** 保留熟悉的 Node.js 宿主，用 Lynx 渲染应用界面，因此基础运行时无需打包浏览器内核。

<span id="light-weight-and-fast" />

- **下载体积。** [Lynxtron 0.0.28 运行时 ZIP](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) 在 macOS arm64 和 Windows x64 上分别为 **24 MB** 和 **35 MB**；同平台的 [Electron 44.3.0 运行时 ZIP](https://github.com/electron/electron/releases/tag/v44.3.0) 分别为 **130 MB** 和 **158 MB**。
- **启动。** 在抖音 PC 的 Windows 线上实验中，Lynxtron 让首屏展现耗时中位数比对照组缩短 **27%**。实验组内，走 Lynxtron 路径的冷启动首刷 P90 为 **10.8 秒**，常规路径为 **19.0 秒**，相差 **43%**。

## 开发者与编程智能体都能沿用熟悉的 Electron API \{#multiplatform}

如果你开发过 Electron 应用，这套启动流程会很熟悉：等待应用就绪、创建窗口、加载界面。你可以复用大部分 Node.js 宿主代码，再用 Lynx 构建 UI。参见 [Electron 迁移指南](/zh/lynxtron/learn/Migrating-From-Electron)。

```text
Electron    [Node.js 主进程] ↔ [Chromium 渲染进程]
Lynxtron    [同一进程：Node.js 宿主 ↔ Lynx UI]
```

```ts
import { app, LynxWindow } from '@lynx-js/lynxtron';

app.whenReady().then(() => {
  const win = new LynxWindow({ width: 800, height: 600 });
  win.show();
  win.loadFile('main.lynx.bundle');
});
```

你和编程智能体可以先[在浏览器里迭代 UI](/zh/lynxtron/learn/running-on-web)，再回到桌面应用验证系统能力。跨平台笔记示例共用同一套 UI 和笔记 API：桌面端写入文件，Web 端使用浏览器存储。

## 接入已有的原生代码和网页 \{#natively-extensible}

已有的原生渲染代码可以接入 Lynx 界面。在原生纹理画布示例中，原生代码绘制外部纹理，Lynx 负责控件和交互。参见 [Lynx 原生库指南](/zh/lynxtron/Native-Libraries/Lynx-Native-Libraries)。

需要嵌入现有网页时，可选的 [CEF WebView](/lynxtron/api/@lynx-js/cef-webview/index.mdx) 提供一致的 Chromium 内核。[0.0.28 的独立下载包](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28)在 macOS arm64 和 Windows x64 上分别为 **126 MB** 和 **161 MB**。对于可以使用平台自带内核的应用，我们也计划支持[系统 WebView](https://github.com/lynx-family/lynxtron/issues/395)。

和 Electron 一样，Lynxtron 的 [Node.js 宿主支持 Node-API addon](/zh/lynxtron/Native-Libraries/NodeJS-Native-Modules)。我们也在[将 Node-API 带到更多 Lynx 原生平台](https://github.com/lynx-family/lynx/discussions/845)，方便开发者复用原生代码。
