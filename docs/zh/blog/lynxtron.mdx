Electron 让开发者可以用熟悉的 Web 技术和桌面 API 高效构建应用，但随应用分发的 Chromium 内核让基础包体较大，运行时的内存占用也较高。

**[Lynxtron](/zh/lynxtron/)** 为希望保留这种开发体验的团队提供了一个更轻量的选择。它以 Node.js 为宿主，用 Lynx 渲染界面，基础运行时不内置浏览器内核。开发者可以沿用熟悉的 Electron 风格 API 管理窗口和应用生命周期，像开发 Web 应用一样编写组件和样式。

<span id="light-weight-and-fast" />

- **下载体积。** Lynxtron 0.0.28 的运行时压缩包在 macOS arm64 上为 **24 MB**，在 Windows x64 上为 **35 MB**。相同平台上，Electron 44.3.0 分别为 **130 MB** 和 **158 MB**。[Lynxtron 发布包](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28) · [Electron 发布包](https://github.com/electron/electron/releases/tag/v44.3.0)
- **首屏耗时。** 在抖音 PC 的 Windows 线上实验中，Lynxtron 组的首屏展现耗时 P50 比对照组缩短 **27%**。
- **冷启动。** 在实验组内，走 Lynxtron 路径的冷启动首刷耗时 P90 为 **10.8 秒**，常规路径为 **19.0 秒**，缩短 **43%**。

## 面向编程智能体的 Electron 风格 API 与架构 \{#multiplatform}

让编程智能体迁移一个 Electron 应用，它可以直接从现有的 Node.js 主进程脚本入手。我们保留了熟悉的生命周期和窗口 API，让智能体可以沿用等待应用就绪、打开窗口等写法。渲染架构则有所变化：Electron 在独立的 Chromium 进程里渲染页面，Lynxtron 在同一进程的主线程上渲染界面，在后台线程执行业务逻辑。[了解 Lynxtron 架构](/zh/lynxtron/learn/what-is-lynxtron)。

![在 Lynxtron 中，Node.js 宿主和 Lynx 渲染共用主线程，UI 业务逻辑运行在后台线程。](https://lf-lynx.tiktok-cdns.com/obj/lynx-artifacts-oss-sg/lynx-website/assets/lynxtron/lynxtron-architecture.png)

例如，Electron 应用通常在 `app.whenReady()` 之后打开第一个窗口。在 Lynxtron 中也一样，创建 `LynxWindow`，然后加载编译好的 Lynx bundle 即可。

```ts
import { app, LynxWindow } from '@lynx-js/lynxtron';

app.whenReady().then(() => {
  const win = new LynxWindow({ width: 800, height: 600 });
  win.show();
  win.loadFile('main.lynx.bundle');
});
```

## 可扩展性 \{#natively-extensible}

Lynx 保留了类似 Web 的界面开发体验，也让你能把桌面应用已有的原生库和组件带进新界面。原生库可以向 Lynx 暴露方法，原生组件也可以作为元素参与布局。[了解 Lynx 原生库](/zh/lynxtron/Native-Libraries/Lynx-Native-Libraries)。

**WebView。** WebView 也是可以嵌入 Lynx 的组件，适合保留应用中已有的网页。我们计划支持[系统 WebView](https://github.com/lynx-family/lynxtron/issues/395)，使用操作系统提供的浏览器内核。已提供的 [CEF WebView](/zh/lynxtron/api/@lynx-js/cef-webview/index.mdx) 则随应用分发 Chromium，让网页在不同平台使用相同的内核。CEF 的独立下载包在 macOS arm64 上为 **126 MB**，在 Windows x64 上为 **161 MB**。[0.0.28 发布包](https://github.com/lynx-family/lynxtron/releases/tag/v0.0.28)

和 Electron 一样，Lynxtron 选择了 [Node-API](/zh/guide/use-native-modules.html?platform=node-api) 作为原生模块接口。我们也在推动[将 Node-API 带到所有 Lynx 原生平台](https://github.com/lynx-family/lynx/discussions/845)，让一份原生模块实现可以跨平台复用。
