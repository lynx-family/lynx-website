现在，Lynx 应用可以直接使用 Rsbuild 构建。配置文件使用标准的 `rsbuild.config.ts`，CLI 和插件也沿用 Rsbuild 的用法。Lynx 特有的适配由 [`pluginLynx`] 提供。

- **新项目**：推荐直接使用 Rsbuild。
- **现有 Rspeedy 项目**：可以继续使用，Rspeedy 将继续维护。迁移时，大部分配置可以原样保留，少数配置项需要调整，见[升级与迁移](#升级与迁移)。

## 快速开始

通过官方脚手架创建新项目，按提示选择 Rsbuild 和 TypeScript：

<PackageManagerTabs command="create @lynx-js/lynx@latest" />

安装依赖后，启动开发服务器，通过 [Lynx Explorer](/guide/start/quick-start) 扫码预览：

<PackageManagerTabs command="run dev" />

构建生产环境产物：

<PackageManagerTabs command="run build" />

应用模板和组件库模板都配置了 [Rstest](https://rstest.rs/zh/) 与 [ReactLynx Testing Library](/api/react/testing-library/index)。运行以下命令执行测试：

<PackageManagerTabs command="run test" />

创建 ReactLynx 组件库时，在同一脚手架中选择 Rslib 和 TypeScript，构建配置、类型声明与发布方式见 [Rslib 的 ReactLynx 指南](https://rslib.rs/guide/solution/reactlynx)。

## 从 Rspeedy 到原生 Rsbuild

### Rspeedy 的由来

早期，我们选择 Rsbuild 作为 Lynx 的构建基础，希望复用 Web 生态中已有的构建能力。但 Lynx 与浏览器存在较多差异：Lynx 不需要生成 HTML，部分面向浏览器的配置无法直接使用，模块加载、产物格式和 dev server 也需要专门适配。

如果直接开放全部配置，并由用户自行组合适配插件，用户需要先确认哪些配置适用、哪些能力必须额外接入。因此，我们在 Rsbuild 之上封装了 [Rspeedy](https://lynxjs.org/zh/rspeedy/index.html)，提供独立的配置文件和 CLI，屏蔽不适用的配置，并设置适合 Lynx 项目的默认值。

### 逐步对齐 Rsbuild 配置

后续迭代中，Rspeedy 在模块解析、dev server 和输出等方面支持了更多 Rsbuild 配置，可用范围逐渐接近原生 Rsbuild。

随着支持的配置增多，两套接口的维护成本也随之增加。用户需要确认 Rsbuild 配置在 Rspeedy 中是否可用，我们也需要跟进上游变化，实现新增配置，并更新类型校验和文档。

为此，我们逐项梳理了 Rspeedy 与 Rsbuild 的配置差异。大部分配置可以直接沿用 Rsbuild，只有 Lynx 特有的配置项和默认值需要保留。

### 引入 pluginLynx

我们将 Lynx 特有的配置项、默认值和构建适配抽出为 [`pluginLynx`]，供 Rspeedy 和原生 Rsbuild 共用。

ReactLynx 的编译仍由 [`pluginReactLynx`](/api/packages/react-rsbuild-plugin/functions/pluginReactLynx) 负责。原生 Rsbuild 项目如果不需要调整 Lynx 特有的配置项，只需添加 `pluginReactLynx()`。它会自动添加使用默认配置的 [`pluginLynx`]，已显式配置 [`pluginLynx`] 时不会重复添加。

未来，其他框架也可以通过各自的插件接入，复用 [`pluginLynx`] 中的 Lynx 适配。

#### 配置迁移对照

各类配置在原生 Rsbuild 中的用法如下：

| 配置                                                                                                                                 | 在原生 Rsbuild 中                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 静态资源、CSS、模块解析、dev server 等通用配置                                                                                       | 与 Rsbuild 一致，参考 Rsbuild 文档                                       |
| [`output.filename.bundle`](/api/build/output/filename/bundle)（设置最终的 `.lynx.bundle` 文件名）                                    | 传给 `pluginLynx({...})`                                                 |
| [`output.minify.mainThreadOptions`](/api/build/output/minify/main-thread-options) 与 `backgroundOptions`（分别压缩主线程和后台线程） | 传给 `pluginLynx({...})`                                                 |
| [`output.dataUriLimit`](/api/build/output/data-uri-limit)、[`output.sourceMap`](/api/build/output/source-map)                        | 配置接口与 Rsbuild 一致，Lynx 只修改了默认值                             |
| `source.entry` 的字符串简写                                                                                                          | 需要改为对象形式                                                         |
| `tools.rsdoctor`                                                                                                                     | 改为接入 [Rsdoctor 插件](https://rsdoctor.rs/zh/guide/start/quick-start) |
| [`performance.profile`](/api/build/performance/profile)                                                                              | 暂时仍可通过 `pluginLynx` 配置，后续会逐步淘汰                           |

完整的配置项和默认值差异见 [Lynx 构建配置参考](/api/build/index)。

### 使用原生 Rsbuild 的优势

- **配置直接参照 Rsbuild 文档。** 此前使用 Rsbuild 配置时，需要先确认它在 Rspeedy 中是否可用、名称是否一致。现在可以直接参照 [Rsbuild 文档](https://rsbuild.rs/zh/)，Lynx 特有的配置项则查看 [Lynx 构建配置参考](/api/build/index)。
- **直接使用 Rsbuild 插件。** 例如接入 Rsdoctor 时，不再使用 Rspeedy 的 `tools.rsdoctor`，直接参考 [Rsdoctor 的快速上手](https://rsdoctor.rs/zh/guide/start/quick-start)配置即可。
- **工具链一致。** 应用使用 Rsbuild，组件库使用 Rslib，测试使用 Rstest，它们的配置风格和文档体系一致。
- **Agent 更容易理解配置。** 配置直接遵循 Rsbuild 的用法，Agent 不需要再理解 Rspeedy 与 Rsbuild 之间的配置转换。可安装 [Rstack Agent Skills](https://github.com/rstackjs/agent-skills) 中的最佳实践技能：

<PackageManagerTabs
  command="skills add rstackjs/agent-skills --skill rsbuild-best-practices"
  dlx
/>

同一仓库还提供 Rslib、Rstest 和构建分析相关技能，可按项目需要选用。

### 迁移到原生 Rsbuild

迁移时需要调整以下内容：

1. 将依赖 `@lynx-js/rspeedy` 替换为 `@rsbuild/core`，并安装 `@lynx-js/rsbuild-plugin`。
2. 将项目脚本中的 `rspeedy` 命令改为 `rsbuild`。
3. 将 `tsconfig.json` 中的 `@lynx-js/rspeedy/client` 类型引用替换为 `@rsbuild/core/types`。
4. 将配置文件改名为 `rsbuild.config.ts`，从 `@rsbuild/core` 导入 `defineConfig`。
5. 对照上面的[配置迁移对照](#配置迁移对照)，检查 `source.entry`、`tools.rsdoctor` 和 Lynx 特有的配置项。

以修改 Bundle 文件名为例，先安装 [`pluginLynx`]：

<PackageManagerTabs command="install -D @lynx-js/rsbuild-plugin" />

将 `lynx.config.ts` 改名为 `rsbuild.config.ts`，配置改动如下：

```diff title="lynx.config.ts → rsbuild.config.ts"
 import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin';
-import { defineConfig } from '@lynx-js/rspeedy';
+import { pluginLynx } from '@lynx-js/rsbuild-plugin';
+import { defineConfig } from '@rsbuild/core';

 export default defineConfig({
   source: {
     entry: { main: './src/index.tsx' },
   },
-  output: {
-    filename: { bundle: 'app.lynx.bundle' },
-  },
-  plugins: [pluginReactLynx()],
+  plugins: [
+    pluginLynx({
+      output: {
+        filename: { bundle: 'app.lynx.bundle' },
+      },
+    }),
+    pluginReactLynx(),
+  ],
 });
```

其他 Lynx 特有的配置项同样传入 [`pluginLynx`]。完整迁移步骤见 [Rspeedy 迁移指南](https://lynxjs.org/next/zh/guide/build/rspeedy.html#migrating-an-rspeedy-project)。

### Rspeedy 升级注意事项

继续使用 Rspeedy 的项目，从 0.15 升级时需要注意以下变更：

- **0.17 移除 `dev.client`**：使用该配置项的项目需将其删除。Lynx HMR 统一使用原生 `LynxWebSocketModule`，自定义 Lynx 宿主需提供该模块。
- **0.18 对齐 CSS Modules 默认类名**：开发环境改为 `[path][name]__[local]-[hash:base64:6]`，生产环境不变。可显式设置 [`output.cssModules.localIdentName`](https://rsbuild.rs/zh/config/output/css-modules#cssmoduleslocalidentname) 保留旧行为。
- **0.18 默认关闭开发进度条**：需要时显式开启 [`dev.progressBar`](https://rsbuild.rs/zh/config/dev/progress-bar)。
- **产物路径调整**：0.17 将中间产物目录从 `.rspeedy/` 改为 `.lynx/`，并移除 `output.distPath.intermediate`。`@lynx-js/template-webpack-plugin` 0.14.0 将懒加载 Bundle 的默认目录从 `async/` 改为 `lazy-bundle/`。部署、调试和缓存脚本中若引用了这些路径，需要同步更新。

完整版本记录见 [CHANGELOG](https://github.com/lynx-family/lynx-stack/blob/main/packages/rspeedy/core/CHANGELOG.md)。
