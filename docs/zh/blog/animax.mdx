今天，我们正式发布 [AnimaX](https://github.com/lynx-family/animax)，一套兼容 Lottie 的跨平台动画框架。你可以继续使用 After Effects 创作动画，将形状、图片、文字与透明视频组合起来，在 Lynx 和原生应用中播放。

AnimaX 由字节跳动的工程团队打造，自 2023 年起逐步在 TikTok、CapCut 等字节跳动旗下产品中落地。如今，它已在数十款应用中运行，覆盖 Android、iOS、HarmonyOS、桌面端与 Web，每天承载百亿量级的动画展示。它支撑的场景跨度很大：从开屏、加载态、列表动效这类轻量、高频的基础动效，到电商大促、直播礼物、激励互动，乃至全球性节点活动这类强视觉、高负载的复杂场景。

在 TikTok 的 2024 巴黎奥运活动中，AnimaX 承载了面向全球用户的强视觉动效；在 TikTok 的激励互动玩法里，它需要在大量中低端设备上同样流畅地运行。正是这些场景，推动 AnimaX 在渲染一致性、性能下限和表现力上持续打磨。

Lottie 建立了从 After Effects 到应用的动画交付流程，让设计师创作的动效可以直接进入产品。我们希望沿用这套流程，同时让它容纳更丰富的视觉效果，并减少不同平台之间的适配工作。

当动画包含复杂特效、遮罩和图层合成时，团队需要同时处理效果还原、跨平台差异和渲染开销。AnimaX 围绕这三个问题设计：用[混合图层](#alpha-video)承载复杂效果，用[共享的渲染引擎](#跨平台一致渲染)减少平台差异，并将[耗时的图形任务移出主线程](#减少主线程占用)。

## 沿用熟悉的 Lottie 工作流

很多团队已经围绕 After Effects、Lottie JSON、预览工具、发布流程建立了完整链路。如果为了获得更强的渲染能力就重新定义一种格式，设计师和开发者都需要重新学习，已有产物也很难复用。AnimaX 选择继续解析 Lottie 格式产物，让现有 JSON 能够直接进入新的运行时。

这意味着业务可以先把 AnimaX 当作一个更强的 Lottie 播放器使用，再逐步引入 [Alpha Video](#alpha-video)、[动态属性](#动态属性)和混合图层。对设计师来说，产物组织方式仍然围绕 After Effects 展开；对开发者来说，接入方式仍然是加载动画资源、[控制播放](/animax/lynx/basic-controls)、[监听状态](/animax/lynx/runtime-events)，只是底层换成了更统一的 C++ 渲染管线。

也就是说，项目中[原有的 Lottie 产物可以直接交给 AnimaX 播放](/animax/migrate-from-lottie#复用动画资源)，不需要设计师在 After Effects 中重新导出。

[AFX](/animax/afx) 是 AnimaX 提供的 After Effects 导出插件，可以导出兼容 Lottie 的动画，并将选定的图层导出为 Alpha Video。已有的 Lottie 资源可以继续使用；需要加入透明视频图层时，再通过 [AFX 导出](/animax/afx#快速入门)。

## 同一份动画，更一致、更流畅

AnimaX 使用 C++ 运行时和 [Skity](https://github.com/lynx-family/skity) 渲染引擎，为已有动画提供共享的绘制实现，并将耗时的图形任务移出主线程。这些能力来自播放器本身，无需为此重新制作动画。

### 跨平台一致渲染

多端动画最难处理的不是“能不能播放”，而是“播放出来是不是一样”。

在传统方案里，Android、iOS、Web 往往各自依赖不同渲染实现。同一个效果，Android 侧用 Skia 能正常绘制，iOS 侧若改用 Core Graphics 或其他实现，就可能出现细节偏差。即使只是形状图层上的模糊效果，也可能在一个平台正常，在另一个平台缺失。平台扩展到 HarmonyOS、桌面端或更多容器时，这种差异会继续放大。

AnimaX 把核心逻辑收敛到 C++，并通过 [Skity](https://github.com/lynx-family/skity) 统一绘制行为。平台侧只需要提供必要的窗口、纹理、资源加载和事件能力，动画解析、图层计算、绘制顺序和大部分渲染逻辑都由同一套引擎完成。这样做不能消除所有平台差异，但能把差异控制在更小的边界里，避免每接入一个新平台就重新面对一套播放器实现。

基于 [Skity](https://github.com/lynx-family/skity) 的自渲染能力，AnimaX 可以在统一的图形管线里支持更多[绘制特性和高级动效](/animax/feature-support#效果)，减少对平台原生绘制能力差异的依赖。AnimaX 在多类 After Effects 特性上比 Lottie 支持更多能力，完整对比见 [功能支持](/animax/feature-support)。

### 减少主线程占用

复杂动画最容易拖慢页面的地方，通常不是播放状态本身，而是持续的图层计算、遮罩处理、混合和绘制。它们如果集中在 UI 线程上，就会和页面滚动、布局、手势响应抢资源，低端设备上尤其明显。

AnimaX 的自渲染架构允许耗时渲染任务放到非 UI 线程执行。对于包含大量蒙层、遮罩、特效和图层合成的动画，这可以显著降低主线程压力，把卡顿风险从页面交互链路里移出去。

Android 上差距最明显：AnimaX 主线程稳定在 60 FPS，Lottie 为 37.5 FPS，而 AnimaX 的进程 CPU 反而更低（约 0.71 核对 1.03 核）。渲染移到 GPU 线程后，主线程留出了更多余量。iOS 上两者帧率持平，这符合 Lottie iOS 通过 Core Animation 把部分播放工作交给系统渲染的表现。Web 上帧率基本一致，AnimaX 的 WebGL 后端把资源放在 GPU 侧，JS Heap 和 Chrome 进程 RSS 都更低。

内存需要结合口径来看。Android 上 AnimaX 的 Native Heap 和 Java Heap 增量更低，Graphics 增量更高；iOS 上 Phys Footprint 更高。这是自渲染引擎把工作集放进图形缓冲区、纹理和渲染缓存后的预期形态，在 iOS 上这部分会直接计入进程 footprint。

### 线上业务中的表现

Benchmark 只覆盖单一动画在少数设备上的表现，线上业务是另一种验证。从多条业务线的迁移结果来看，结论是一致的：AnimaX 抬高的是体验的下限，而不是峰值。

- **激励互动场景**：中间分位帧率提升约一半，低分位也有明显改善，CPU 与内存基本持平。
- **电商营销场景**：Lottie 在低分位设备上只能跑到十几帧，AnimaX 在各分位基本跑满；动画资源的加载耗时也明显缩短。
- **大型活动**：在限帧 30 FPS 的条件下，AnimaX 在双端全分位都能跑满，而 Lottie 的高分位卡顿明显。
- **稳定性**：与 Lottie 相比没有显著差异，ANR 和卡顿指标略有下降。

这与 Android 上的 Benchmark 结论一致：把渲染移出 UI 线程，不会让本来就流畅的设备更快，它解决的是 UI 线程已经饱和的那些情况。

## 扩展动画的表现与控制

### Alpha Video

纯矢量图层无法表达所有 After Effects 效果。很多动效里会同时出现形状图层、图片、文字、模糊、遮罩、光效或 3D 效果。如果强行把这些内容全部转成图片序列再打包进 Lottie，往往会遇到体积过大、还原不稳定、端能力不一致的问题。

AnimaX 支持 [Alpha Video](/animax/alpha-video) 图层。对于复杂度高、暂时不适合用矢量实现，或者本来就更适合视频表达的效果，设计师可以通过
[AFX 导出指南](/animax/afx)
把相关图层[组织并导出为透明视频图层](/animax/alpha-video#使用方法)，再与 Lottie 形状、图片和文本图层一起播放。这样既保留了 After Effects 的表达能力，也避免把所有视觉细节都压到纯矢量图层里。

### 动态属性

动效进入业务页面以后，常常不只是自动播放一遍。页面可能需要根据用户状态[替换图片](/animax/lynx/dynamic-properties#设置图片资源)，根据语言[切换文本](/animax/lynx/dynamic-properties#设置文本字体资源)，根据主题更新颜色，或者在交互发生时[调整某个图层的属性](/animax/lynx/dynamic-properties#更新其他图层属性)。

AnimaX 对这类运行时修改做了专门优化，并提供更直接的 API 来替换图片、字体、文本等资源。业务可以把动画产物当作一个可配置的运行时图层，而不是一段完全封闭的视频或一组难以复用的 UI 片段。设计师仍然可以在 After Effects 里组织动画，开发者则可以在运行时把真实业务数据填进去。

更多用法见 [动态属性](/animax/lynx/dynamic-properties)。

## 立即体验

AnimaX 已发布在
[lynx-family/animax](https://github.com/lynx-family/animax)
仓库中，并提供 Android 和 iOS 原生示例。对于 Lynx 应用，可以直接使用
[`<animax-view>`](/api/elements/built-in/animax-view)
元素播放 AnimaX 动画；也可以在示例文档中直接预览播放效果。

若要在原生平台接入，已有 Lottie 方案可以先参考 [从 Lottie 迁移到 AnimaX](/animax/migrate-from-lottie)，再按照 [原生接入指引](/animax/native/quick-start) 完成 iOS 或 Android 接入。[播放控制与生命周期](/animax/native/playback)、事件和状态查询见 [原生 API 参考](/animax/native/api/animax-view)。

你可以先从 [AnimaX 简介](/animax/introduction)了解整体能力，再跟随
[快速开始](/animax/start/quick-start)
跑通最小示例。如果动画资源来自 After Effects，可以继续阅读
[AFX 导出指南](/animax/afx)，了解 Alpha Video 图层如何被生产出来并和 Lottie 产物一起播放。

后续平台支持也已在规划中：

- HarmonyOS 与 Web 端预计于 2026 年 Q3 陆续发布，同期我们还会封装并推出 LynxUI AnimaX 组件，让 AnimaX 能以更统一的组件形式接入 LynxUI 体系。
- Desktop 端的开源则计划在 2026 年 Q4 完成。

AnimaX 使用 Apache-2.0 许可证，并在开源仓库中持续演进。欢迎在
[lynx-family/animax 仓库](https://github.com/lynx-family/animax)
提交问题、讨论需求或参与贡献。

AnimaX 不试图替代设计师熟悉的 Lottie 工作流，而是在这条工作流之上补齐更完整的渲染、合成和运行时控制能力。对于需要在多端稳定交付复杂动效的团队，它提供了一条更可控的路径。
